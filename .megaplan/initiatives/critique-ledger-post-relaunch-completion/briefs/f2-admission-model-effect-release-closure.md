# F2 — Enforce selector/result, admission and replay closure

## Outcome

Close the VJ24 failure category on every retained state-mutating Critique entry
point and effect class, then issue the category release decision required before
ordinary v3 execution/publication authority expands.

## Scope

Enforce one selector/task-output and accepted-result contract; one non-bearer
admission receipt over the canonical action envelope; pinned runtime and
provider-route/capability attestation; and the exact occurrence-keyed VJ24
replay. Unproven entry points/effect classes remain hard-denied. Broad unrelated
T1.1-T1.6/T2.x/T3.x route/effect-family and zero-debt release inventory remains
preserved, nonblocking work in `../UNFINISHED_WORK.md` and the Custody Control
Plane.

## Locked decisions

- Megaplan owns selector/task semantics; WBC owns the versioned boundary
  declaration and evidence. Finalizer, admission, executor, repository auditor,
  VJ19 and VJ24 consume the same content-addressed version/hash.
- A prospective task output is typed `DEFERRED_TASK_OUTPUT`, never accepted.
  Only an accepted result envelope can satisfy it.
- Every physical model attempt has owner-bound transport evidence and typed
  health; only `SUCCEEDED` may yield a semantic result.
- The admission receipt is a content-addressed, non-bearer reference. Every
  action rereads the current Run Authority grant/fence and Custody lease/epoch,
  then checks exact WBC evidence; a stale receipt cannot authorize action.
- Provider route/capability and role-scoped credential facts are admission
  evidence, not positive authority. No profile alias or fallback can mint a
  grant, occurrence, lease, attempt or effect permission.
- Every external effect has durable WBC intent/outcome evidence and sticky
  UNKNOWN/no-redispatch behavior under current Run Authority and Custody gates.

### Architecture-fit gate

F2 consumes the exact accepted Run Authority, Custody, WBC and
lifecycle/TransitionWriter API revisions named by F1. Its derived inventory of
state-mutating launch, resume, override, adoption, bootstrap, refresh and replay
call sites must identify one canonical action envelope per path. Every other
path is denied, read-only or explicitly expiring. A pending generic substrate
stays action-off or is delivered under its canonical owner, never forked here.

## Root acceptance (required, not advisory)

The initiative-local
[`../evidence/p2-control-plane-mapping-20260804.md`](../evidence/p2-control-plane-mapping-20260804.md),
[`../evidence/incident-specific-control-amendment-20260804.md`](../evidence/incident-specific-control-amendment-20260804.md)
and occurrence-specific
[`../evidence/immediate-fix-and-category-hardening-20260805.md`](../evidence/immediate-fix-and-category-hardening-20260805.md)
are required inputs. F2 must prove:

- Finalization emits `selector_task_output_contract.v1` with normalized
  selector, producing task, output type/path, declared writes, validation
  timing, test budget and plan revision. Finalizer, admission, executor,
  repository auditor, VJ19 and VJ24 persist the identical contract hash.
- A stale declaration requires an accepted new plan revision; any
  plan/runtime/validator/normalizer mismatch is typed binding drift and requires
  migration before dispatch.
- T18/T23 cannot advance without accepted result envelopes binding declared and
  observed writes, tests/budgets, acknowledgements, content/tree hashes, source,
  runtime, attempt and WBC acceptance.
- Every retained launch/resume/override/adoption/bootstrap/refresh/replay path
  consumes the same non-bearer admission receipt or is hard-denied. Any
  break-glass path is occurrence/effect-scoped, expiring, audited, and still
  revalidates Run Authority + Custody + WBC.
- Orchestration, task and validation provider routes use one role-scoped
  resolver with redacted credential/capability attestation before resource or
  lease acquisition and again on resume. Generated commands use the pinned
  runtime/interpreter/import identity.
- Marker, tmux, PID, heartbeat, snapshot or provider facts alone cannot produce
  an executing decision. Host-side coherent reads expose stale/duplicate
  projections as UNKNOWN and never authorize effects.

These obligations require source, installed-generation, crash/restart,
hostile-replay and exact-receipt evidence for each load-bearing contract and
retained state-mutating entry point/effect class. Retired or disabled routes
need denial/no-capability proof, not provider live canaries.

## Bound inputs

The T6.2 handoff supplies the frozen CL2-CL5 brief hashes, accepted cursor,
completed/unresolved task identities and predecessor manifests. F2 cannot
reinterpret or broaden them.

The immediate migrated-child launch may rely on the existing finalized
`task_contract_hash` plus the shared selector normalization/regression described
in the migration cutline. F2 owns the broader
`selector_task_output_contract.v1` schema and its identical digest across every
consumer; that category-wide contract is not a prerequisite for the first
child's migration receipt.

## Constraints

Do not re-run or widen the accepted Stage-A canary merely to collect evidence.
No broad production authority until F1 and F2 completion manifests both exist.

## Done criteria

- Contract fixtures prove legal prospective deferral, accepted-envelope-only
  satisfaction, stale-declaration migration, drift rejection and no advance on
  empty/incomplete envelopes.
- A generated call-site inventory proves set equality: every retained
  state-mutating entry point consumes the same canonical action envelope; every
  other discovered path is denied or read-only.
- The exact VJ24 replay, under concurrent triggers, restart and repeated polls,
  yields exactly one canonical repair request, one accepted Run Authority
  decision, one Custody claim, one WBC fixer attempt, one notification intent
  and at most one provider effect. Duplicate inputs are idempotent no-ops.
- Provider rejection or ambiguity persists `INDETERMINATE` and cannot resend.
  The same text under a new accepted state version creates a new occurrence
  only when the resolver recurrence policy permits it.
- The category release decision binds the exact integrated/installed generation,
  owner API revisions, selector/result contract, migration receipt, replay
  evidence and denial manifests for disabled surfaces.
- Architecture-fit receipt proves no parallel authority, watcher, queue,
  snapshot authority or persistence substrate was introduced.

## Touchpoints

Megaplan plan contracts, finalization, validation selection, result envelopes,
Run Authority admission, Custody, WBC, provider/credential resolution, pinned
runtime generation, status projections and the category-relevant portions of
T1.1-T1.4/T1.6/T2.2/T2.4-T2.6/T3.5-T3.6/T8.3 evidence.

## Anti-scope

Do not implement generic Custody substrate, prove every unrelated configured
route/effect family, close broad zero-debt release inventory, execute CL2 feature
work, publish its PR, deploy the product, or close the incident.
