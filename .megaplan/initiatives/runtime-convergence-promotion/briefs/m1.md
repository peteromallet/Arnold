# Runtime Convergence and Guarded Promotion

## Outcome

Deliver and certify one immutable integration revision `R` descended from
`d38c3980a6`, then promote maintenance and Astrid to separate runtime roots at
`R` using the repository's manifest/attestation/cutover machinery. The initial
candidate is `6ea4111196`, which restores the complete `config` parser contract.

Read `../decisions/pasted-text-1.txt` and `../NORTHSTAR.md` before planning.

## Scope

- Reconfirm live remote lineage, runtime manifests, markers, leases, PIDs,
  launch seeds, chain state, and dependency proofs before mutation.
- Certify the eight maintenance commits from `4ef83c15d9` through
  `d38c3980a6` plus the bootstrap successor.
- Verify equal-mode reconciliation produces `selected_shas: []`, typed
  `coincident_ref` evidence, and the complete candidate inventory.
- Run focused changed-seam tests, runtime manifest/provenance/attestation/
  cutover tests, CLI smoke tests, and the broadest practical backstop.
- Build two new immutable per-epic roots at exact `R`.
- Recompute frozen dependency specification and venv content digest. Reuse a
  generation only when both proofs are identical; otherwise build a new
  content-addressed generation.
- Run a disposable canary with isolated state.
- Promote maintenance first while it remains quiescent. Promote Astrid only at
  a proven between-milestone seam.
- Capture pre/post identities and rollback receipts; retain all old roots.

Out of scope: unrelated cleanup, runtime GC, and resolving DeepSeek billing.

## Constraints

- Worktree-first/PYTHONPATH runtime architecture; no classic editable-install
  shortcut and no ambient Python.
- Never mutate a live runtime candidate in place.
- Never bypass runtime-root ownership checks, CAS fences, launch-seed
  validation, or chain runtime binding.
- Do not cut over when marker, lease, process, manifest, chain, or live import
  identities disagree.
- Do not call the DeepSeek route known to return HTTP 402. Use deterministic
  fixtures and Codex review.
- Preserve dirty operational/documentary artifacts without merging them into
  the runtime revision.
- Roll back immediately on identity divergence, import failure, duplicate
  dispatch, cursor regression, new test failure, or non-empty equal-mode
  selection.

## Done Criteria

1. `R` is clean, published, descended from `d38c3980a6`, and records the
   complete test commands/results.
2. `config show`, root `--help`, `status`, plan parsing, and source-root import
   smoke tests pass under the frozen generation interpreter.
3. Focused and runtime safety suites pass with no unexplained collection delta.
4. Equal-mode reconcile evidence is complete and selects no commits.
5. Maintenance and Astrid have distinct clean runtime roots at exact `R`.
6. Both manifests bind the same independently verified dependency-generation
   proof, including equal venv digest.
7. For each epic: manifest root/revision, chain engine root, marker identity,
   launch seed, process identity, and live imports agree.
8. Maintenance remains intentionally blocked until its provider route is safe;
   no 402 retry storm occurs.
9. Astrid promotion occurs only with no active phase and coherent fresh lease;
   one full post-cutover phase shows no duplicate dispatch.
10. Rollback receipts restore the complete previous identity vector and old
    roots remain present.
