# M4 — Composition, Migration, and Authoring Experience

## Outcome

Complete the Megaplan migration, mechanically compose workflow completion
across supported durable topology, and make the standard pleasant to author,
inspect, test, and diagnose without hand-maintained completion paperwork.

## Scope

### In

- Generate workflow completion from child bindings for sequence, branch, loop,
  fanout/fanin, suspension/reentry, effects, and rework.
- Implement a total child-disposition mapping, including selected-path proof,
  admitted iteration/child-set equality, nonterminal propagation, failure
  policy, and transitive waiver taint.
- Migrate remaining Megaplan planning, gate, loop, execution, human,
  finalization, review, delivery, override, recovery, and compatibility paths.
- Make new durable subjects fail closed when no valid spec/binding exists.
- Generate boundary/completion registries from canonical source; retain old
  tables only as negative/parity fixtures.
- Provide authoring templates and lints so pure helpers need no declaration,
  standard durable steps receive generated obligations, and authors declare
  only domain-specific semantics.
- Generate canonical machine completion records and disposable Markdown views
  showing obligations, evidence, verifier identity, waiver/non-action
  justification, timing, and resolution.
- Generate focused human-verification requests for obligations that truly
  require human authority.
- Remove or fence every old independent completion writer after installed and
  cloud conformance passes.

### Out

- No stable public platform promise.
- No unrelated second consumer.
- No unsupported quorum/race/first-wins semantics.
- No manual recreation of generated manifests.

## Locked Decisions

- Workflow specs compose from admitted children rather than restating them.
- Unselected paths are proven not applicable, never silently satisfied.
- Every admitted loop iteration and fanout child receives a terminal or
  explicitly permitted disposition.
- Markdown is a projection, not the completion record.
- Compatibility readers may remain; compatibility writers may not.

## Open Questions

- Which authored API yields the smallest domain-obligation declaration while
  retaining source-located diagnostics?
- Which legacy projections must remain for external readers and for how long?
- What focused installed/cloud scenarios prove that editable and packaged
  execution consume identical spec/binding identities?

## Constraints

- Target no more than two weeks; split unsupported topology into later tickets
  rather than weakening semantics.
- Preserve current accepted Megaplan behavior and output schemas.
- No per-helper contract explosion.
- Projection rebuilds must not affect acceptance.
- Every temporary bridge needs an owner and deletion test.

## Touchpoints

- workflow compiler/source maps and boundary contracts
- Megaplan native workflow sources and remaining phase adapters
- completion/recovery/status projections
- CLI inspection, lint, test, and generated Markdown views
- editable-install, wheel/sdist, and cloud conformance

## Done Criteria

- Exact inventory equality holds among admitted durable subjects, bindings,
  required evidence, verdicts, consumed decisions, and terminal outcomes.
- Supported sequence/branch/loop/fanout/suspension/effect/rework scenarios have
  deterministic aggregation and negative fixtures.
- Waiver taint remains visible at the root; blocked/suspended/quarantined
  children keep parents nonterminal.
- An unfamiliar author can add a standard durable step without hand-writing
  generated obligations and receives actionable diagnostics for missing domain
  semantics.
- Machine and Markdown views regenerate from immutable evidence and expose
  timestamps, failures, attempts, rework, waivers, and resolution.
- Editable, installed, and cloud runs use the same content-addressed completion
  identity.
- All legacy completion writers are removed or mechanically proven inert.
- M4 publishes the experimental public-candidate surface and extraction
  handoff for M5.

## Anti-Scope

Do not label a Megaplan import path “generic” or stabilize the API before M5's
independent consumer challenges it.
