# M2 — Admission, Binding, and Evidence Evaluation

## Outcome

Make admitted completion bindings immutable and evaluable against exact scoped
evidence, with total candidate-disposition semantics and atomic integration
with the existing acceptance transaction.

M2 hands M3 an authoritative but narrowly enabled binding/evaluator nucleus,
still guarded from broad Megaplan migration.

## Scope

### In

- At compile/install, derive workflow and durable-step spec templates.
- At finalization, accept proposed task/rework obligations.
- At admission, validate, augment, bind, hash, and freeze exact specs.
- Bind subject/attempt/generation, semantic path, source/tree/runtime and asset
  digests, component/dependency locks, Run Authority fence, Custody target and
  epoch, WBC version, store incarnations/restore generations, cursor vectors,
  child/dependency set, and admission receipt.
- Reject evidence outside the binding even when human-readable IDs match.
- Evaluate one proposed candidate disposition at a time and require obligations
  for blocked, suspended, failed, waived, cancelled-pending-reconciliation, and
  quarantined states.
- Enforce proof-mode semantics, including complete-capture requirements for
  absence and exact-set checks.
- Enforce verifier independence using implementation/code provenance, producer
  identity, trust/authority domain, and direct primary-evidence access.
- Propagate waiver scope, authority, expiry, and immutable taint.
- Atomically join the verdict with the current Run Authority/Custody/effect
  prerequisites in the existing acceptance transaction.
- Provide deterministic explanations for unsatisfied, unknown, stale,
  inadmissible, and waived obligations.

### Out

- No broad phase migration.
- No Markdown or editor UX beyond minimal diagnostic output.
- No second consumer.
- No new production store.

## Locked Decisions

- Admission is the only freeze point for a durable binding.
- Resume consumes the pinned binding; changed semantics mean new attempt,
  explicit migration, or quarantine.
- Incomplete evidence yields `unknown`, not satisfied absence.
- A waiver never becomes clean parent acceptance.
- A proposed disposition is data, not authorization.

## Open Questions

- Which existing acceptance transaction hook should consume the evolved verdict
  without widening its authority?
- How should multi-store cursor vectors be normalized and hashed?
- Which current evidence producers qualify for each initial independence class,
  and which require an independent implementation?

## Constraints

- Target no more than two weeks.
- Preserve linearizable acceptance and current custody fencing.
- No wall-clock-only evidence window.
- No cross-attempt, cross-generation, cross-restore, or changed-runtime
  evidence stitching.
- Migration adapters must be deterministic and observable.

## Touchpoints

- post-M11 admission and acceptance transaction code
- Run Authority and Custody bindings
- `arnold/workflow/semantic_evidence.py`
- `arnold/workflow/boundary_evidence.py`
- Megaplan completion/evidence orchestration
- primary-store and cursor identity adapters

## Done Criteria

- Exactly one binding can be admitted per durable subject occurrence.
- Re-admission is idempotent for identical content and rejects conflicting
  content.
- Changed-code resume, stale fence, old custody epoch, wrong store
  incarnation, and cross-attempt evidence all fail closed.
- Each candidate disposition has tested obligations and transition semantics.
- Presence, absence, set-equality, and aggregate proof modes have positive,
  negative, and incomplete-capture tests.
- Nominally different wrappers over the same verifier implementation fail the
  configured independence policy.
- Acceptance remains atomic under concurrent contenders.
- M2 publishes the binding/evidence-scope contract, verifier registry policy,
  acceptance integration map, and M3 enablement flag/entry conditions.

## Anti-Scope

Do not make the evaluator a route authority or permit a compatibility adapter
to manufacture missing evidence.
