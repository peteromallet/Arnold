# M1 — Contract and Identity Kernel

## Outcome

Land the smallest neutral `CompletionSpec -> CompletionBinding ->
CompletionVerdict` contract kernel as adapters over existing Arnold/Megaplan
machinery, plus shadow generation and a reproduced negative fixture for the
captured M10/M11 false-done and unroutable-review-rework failures.

The milestone hands M2 a versioned schema, registry/admission lint contract,
carrier inventory, divergence ledger, and executable golden fixture. It does
not make the new contracts authoritative.

## Scope

### In

- Inventory the post-M11 canonical carriers for Step-IO, task contracts,
  Workflow Boundary Contracts, evidence references/producers,
  `CompletionVerdict`, Run Authority, Custody, admission, and acceptance.
- Define neutral schemas/types for `CompletionSpec`, stable obligations,
  candidate dispositions, proof modes, `CompletionBinding`, and the evolved
  verdict shape.
- Mechanically define a durable semantic subject. A unit is durable only by
  explicit authored declaration or admission and must be declared when it owns
  typed terminal outcomes, registered effects, suspension/reentry,
  checkpoint/retry/durable-child identity, authority/custody, or cross-boundary
  artifacts.
- Lint pure helpers so they cannot hide those responsibilities; fold their
  behavior into the containing source/runtime digest.
- Freeze identity rules: stable `obligation_id`, canonical `spec_hash`,
  `binding_hash`, tombstoning, and exact verdict-reuse tuple.
- Add adapters over existing completion/boundary/task records. Do not introduce
  a new evidence registry, receipt store, acceptance path, or task scheduler.
- Generate shadow specs for representative Megaplan durable subjects.
- Reproduce a deterministic fixture from captured M10/M11 history proving:
  legacy `done` without an accepted attempt is not completion; `REVIEW` is not
  executable; a new review finding is proposed as a new subject; and accepted
  evidence for unrelated tasks is preserved.
- Record every shadow divergence as old-system defect, new-generator defect,
  or reviewed intentional difference.

### Out

- No live acceptance cutover.
- No workflow-wide aggregation beyond the schema needed for later composition.
- No public stable Arnold API.
- No broad migration of Megaplan phases.

## Locked Decisions

- The copied design proposal and epic North Star are normative.
- Extend the existing `CompletionVerdict`; do not create a competing verdict.
- Candidate dispositions are explicit. Quarantine and suspension are
  nonterminal.
- Initial proof modes are `presence`, `complete_capture_absence`,
  `set_equality`, and `aggregate`; no general logic DSL.
- One evidence item may support several explicitly linked obligations but
  cannot be double-counted to prove multiplicity.
- Generated projections have no authority.

## Open Questions

- Which post-M11 package owns the neutral schema without creating an
  Arnold-to-Megaplan reverse dependency?
- Which legacy fields are compatibility projections versus canonical inputs?
- What canonical serialization already used by the repository best guarantees
  stable hashing across local, installed, and cloud execution?

Resolve these from current code and fixtures; document the answer in the
handoff rather than relitigating the North Star.

## Constraints

- Target no more than two weeks of skilled engineering work.
- Preserve backward-readable records during shadow mode.
- Use deterministic, source-located lint errors.
- A shadow parity count alone is not acceptance.
- Tests must run against the same editable installation/import identity used by
  the current M11 successor checkout.

## Touchpoints

- `arnold/workflow/`
- `arnold_pipelines/megaplan/orchestration/completion_contract.py`
- `arnold_pipelines/megaplan/orchestration/completion_io.py`
- `arnold_pipelines/megaplan/orchestration/task_satisfaction.py`
- Megaplan admission/finalization and boundary-contract adapters
- focused schema, hashing, fixture, and negative tests

## Done Criteria

- One canonical schema and hashing implementation round-trips deterministically.
- Durable/helper lint has positive and hidden-effect negative fixtures.
- Shadow generation covers workflows, durable steps, dynamic tasks, effects,
  and human suspension without contracting pure helpers.
- The M10/M11 fixture fails the legacy false-done and `REVIEW` pseudo-task
  claims under the new evaluator while preserving unrelated accepted evidence.
- Every shadow divergence has a durable disposition.
- Existing authoritative behavior is unchanged.
- M1 publishes a handoff documenting canonical package ownership, schema/hash
  versions, adapter map, fixture IDs, divergence dispositions, and M2 entry
  conditions.

## Anti-Scope

Do not “clean up” neighboring orchestration, invent generalized policy
languages, or silently move terminal authority into the new schema.
