# Occurrence-bound VJ24 migration primitive

## Outcome

Implement and test the smallest production-shaped control-plane operation
that converts the retained r5/VJ24 failure into one authority-approved child
run. The operation must be safe to run repeatedly and must produce the exact
receipt required by the post-relaunch completion epic.

## Scope

In scope:

- Read and freeze the retained VJ24 parent evidence (plan/chain/runtime
  bindings, batch grant/fence, failure fingerprint, selector/task graph and
  accepted-result status).
- Normalize the selector path once in the shared task-feasibility seam used by
  Finalize and Execute. A missing selector explicitly declared in the task's
  finalized `write_set.paths` is `DEFERRED_TASK_OUTPUT`; an undeclared missing
  selector fails admission. After an accepted task result, rerun the deferred
  validation. The existing `task_contract_hash` is the first-child contract;
  the cross-consumer `selector_task_output_contract.v1` belongs to F2.
- Add a dedicated `occurrence_child_migration.v1` prepare/commit coordinator
  outside the generic override workflow. It must use a real Run Authority
  journal writer and atomic integer-cursor compare-and-append to quarantine the
  parent and allocate a fresh child revision/coordinator attempt and grant/fence;
  then acquire a fresh Custody occurrence/lease/epoch, reserve one WBC
  attempt/effect reference, append the parent→child receipt, and advance the
  parent cursor. It must not create an authority store of its own.
- Quarantine the parent and make same-occurrence resume fail closed. Expose a
  normal child-launch handoff; do not start a provider effect in the prepare
  operation.
- Add deterministic unit/integration fixtures for missing, conflicting,
  replayed and partially written owner records; include crash recovery after
  each owner write and exact deferred-selector rerun. Observer projection
  assertions, notification replay, and category-wide selector schema adoption
  are deferred to the owning F1/F2 hardening work.

Out of scope: changing the live r5 state, launching any r5 or successor
runner, broad Custody Control Plane work, notification-provider delivery,
historical debt sweeps, or unrelated effect families.

## Constraints

- Reuse Run Authority, Custody, WBC, lifecycle/CAS and existing receipt stores;
  do not create a parallel ledger or infer authority from marker/tmux/PID,
  state.json, or a narrative failure summary.
- Parent evidence is immutable. A stale, missing or contradictory owner read
  yields `UNKNOWN`/`INDETERMINATE` and no child or cursor mutation.
- Use deterministic IDs derived from the parent occurrence, contract hashes and
  requested child revision. Identical retries are no-ops; divergent retries
  return a typed conflict.
- The CAS cursor is the authoritative integer parent Run Authority journal
  position. It is not `SourceCursorVector.vector_id` and must be reread from the
  owner immediately before atomic compare-and-append.
- Keep credential/profile selection out of the migration authority decision;
  the later child launch must use the pinned Sol-finalize/GLM-execute profile.

## Done Criteria

- A real command/API and schema are documented and covered by tests; no
  same-occurrence resume path can satisfy the migration receipt.
- Missing declared selectors defer, missing undeclared selectors fail before
  dispatch, existing selectors run, and deferred selectors are rerun only after
  an accepted task result. The narrow regression from `c9239cfe79` is covered;
  the current finalize patch must not silently widen write authority.
- A synthetic parent fixture produces exactly one valid child receipt joining
  Run Authority, Custody and WBC identities, with a fresh fence/epoch/attempt;
  repeated invocation produces no second child or cursor advance.
- Missing owner records, selector-contract drift, stale integer CAS and provider
  ambiguity fail closed with durable diagnostics and no provider effect. The
  owner API must reject synthesized grants/fences/leases.
- Exact migration retries are no-ops, divergent retries conflict, and crash
  recovery after each owner write cannot produce a second child/lease/attempt/
  GLEK. The full VJ24 replay/cardinality proof remains F2.
- The output names the exact handoff files the post-relaunch epic needs; the
  live cloud r5 occurrence remains paused and unchanged during this sprint.
- The prelaunch migration receipt proves admission, custody, and a fresh child
  identity only. Accepted VJ24/T18/T23 envelopes and cursor advance are
  post-launch child outputs consumed by the later T6.2 handoff; this sprint
  must not require or fabricate them.
