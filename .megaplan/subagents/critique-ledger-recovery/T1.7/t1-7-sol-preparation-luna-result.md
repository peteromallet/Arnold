## Bottom line

The ancestor has one reusable local transactional primitive, `SqliteAttemptLedgerStore`, but no shared owner-store boundary. Each owner reinvented persistence. Several stores are advisory, projection-only, or in-memory; several authoritative paths convert unreadable/corrupt state to empty/default state; and four separate sequence patterns can fork under process concurrency. The recommended fix is one neutral SQLite owner-store contract instantiated as a separate database per authority owner, not one cross-owner database. Cross-owner work remains a fail-closed saga.

## Projection/log/artifact separation gaps

- Incident canonical `events.jsonl` shares a directory with disposable `incidents.json` and `problems.json`.
- Critique authority, raw artifacts, registries, WBC SQLite, plan state, and projections share each plan directory.
- Custody projections use their own directory but the same default `~/.megaplan/custody` tree and filesystem; their history itself is unbounded JSONL. Generic projection readers may skip corrupt records (`_core/io.py:2164-2448`).
- `work_ledger.ndjson` explicitly labels itself non-authoritative but has no lock/fsync and skips malformed rows (`observability/work_ledger.py:285-311`). `routing_ledger.jsonl` is best-effort, no fsync, and catches every write exception (`observability/routing_ledger.py:78-147`).
- Cloud status `cloud-status.json`, previous snapshot, projection history and `progress-history.jsonl` all live under `/workspace/.megaplan/status`. Snapshot writes do not fsync file/parent (`cloud/status_snapshot.py:481-542`); progress history appends and periodically rewrites its tail (`:740-789`). These must remain disposable projections.
- The bounded event checkpoint is a good projection model: it pins inode/incarnation/restore generation/byte cursor/hash prefix, bounds the tail, fsyncs publication, and rejects corrupt checkpoints (`observability/event_checkpoint.py:1-11,87-108,206-267,316-380`). It is still co-located with the journal and must not consume canonical reserve.
- FileStore keeps large blobs under its control root; native WBC stores evidence beneath caller artifact roots. No landed byte/inode reserve or quota boundary prevents logs/artifacts/projections from exhausting owner-store commit/WAL/checkpoint capacity.

## Recommended shared boundary

Create a neutral `OwnerStore` API usable by kernel, Run Authority, Custody, WBC, critique, repair and resident code. Back each owner with a separate SQLite database on a canonical-store mount/quota; do not create a single database spanning owners.

Minimum contract:

1. `append(owner, stream, event_id, idempotency_key, expected_head, payload)` executes head check, process-safe sequence allocation, immutable event insert, idempotency comparison, and head update in one `BEGIN IMMEDIATE` transaction.
2. `transact(owner, fn)` is atomic only inside that owner. Cross-owner operations use durable intent/receipt sagas and never infer another owner’s success.
3. `read_authority` returns `Present`, `Absent`, or a typed `ReadFailure/Corrupt/Unsupported`; it never returns empty/default on I/O, decode, checksum, schema, or checkpoint failure.
4. SQLite settings and proof: WAL, `synchronous=FULL`, busy timeout, foreign keys/check constraints, explicit checkpoint/backup/restore, schema/incarnation/restore generation, `PRAGMA integrity_check`, and directory/file durability tests. Extend `SqliteAttemptLedgerStore`; do not fork another partial implementation.
5. `StorageAdmission` checks free bytes and free inodes against a reserve covering the worst transaction, WAL growth, fsync, checkpoint, backup and rebuild. It runs before durable intent and again before external dispatch/receipt. ENOSPC/EDQUOT/short write is typed; post-provider receipt failure becomes `INDETERMINATE`.
6. Projections are generated through a separate `ProjectionStore` root/quota, bounded by rows/bytes/age, deletable and reconstructable. Projection sequence gaps are legal. Canonical readers never fall back to a projection.
7. Large artifacts are content-addressed references `(path/object URI, SHA-256, size, retention class)`, never embedded repeated snapshots.
8. Every public writer requires owner identity, store incarnation and fenced generation. Raw file helpers become private migration readers or are removed; installed entrypoints must resolve the same attested store implementation.

Suggested per-owner databases: `run-authority.sqlite3`, `custody.sqlite3`, `wbc.sqlite3`, `critique.sqlite3`, `recovery.sqlite3`, and the existing resident/plan Store backend. Their transactions must not be combined.

## Required attack/test matrix

- **Real concurrency:** at least 32 independent processes append the same owner stream and contend on the same idempotency key/head. Assert no lost rows, duplicate sequences, divergent heads, or false success. The ancestor’s `test_jsonl_concurrent_appends_are_visible` is sequential and proves none of this.
- **Crash points:** SIGKILL after sequence allocation, WAL append, commit record, fsync, rename/checkpoint, provider response, receipt start and receipt commit. On restart, outcome is exactly committed, absent, or typed indeterminate—never an inferred default.
- **Durability:** fault-inject short write, EIO, ENOSPC, EDQUOT, directory-fsync failure, WAL/checkpoint failure, zero bytes and zero inodes. Validate reserves before intent and dispatch and prove logs/artifacts/projections cannot consume them.
- **Read corruption:** permission denial, unreadable directory, truncated/corrupt DB/WAL, schema mismatch, checksum mismatch, corrupt JSON migration input and missing file after prior incarnation. Every authority read fails closed and preserves diagnostics.
- **Projection independence:** delete, truncate, corrupt, enlarge and roll back every projection. Canonical decisions remain unchanged; one bounded rebuild reproduces the projection; warm reads obey byte/time/RSS ceilings. Keep the existing 60k/710MB sparse checkpoint test and add owner-store large-history equivalents.
- **Migration/restart:** import exact legacy bytes with hash/count/error manifest, fence old writers, switch generation by CAS, restart every installed entrypoint, verify backup restore and restore-generation change, and reject old-generation writes/read fallbacks.
- **Bypass:** static and runtime probes forbid direct writes to legacy JSON/JSONL/NDJSON, raw `record_event`, `flock=False`, scratch ingestion, mutable receipt replacement, and source/installed wrapper drift. Exercise module CLI, tmux, systemd, `/usr/local/bin`, and editable-source paths.
- **Cross-owner failure:** inject failure between Run Authority, Custody and WBC steps; prove no local transaction implies another owner and no effect occurs without all current receipts.
