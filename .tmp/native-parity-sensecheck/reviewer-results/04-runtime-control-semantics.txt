## 2. Ranked Gaps

### GAP-1 [CRITICAL] Suspension is convention, not a runtime primitive
- **Severity**: HIGH
- **Confidence**: HIGH
- **Consequence**: The advertised suspend/resume capability is actually "write a checkpoint artifact and accidentally halt." The neutral executor (`pipeline/executor.py`) has no `SUSPENDED` handling. Gate handler's `"suspend"` route signal maps to `"halt"` via `_LOWERED_STEP_ID_ALIASES` (planning.py:121). Resume re-runs a fresh pipeline from a saved PC, not rehydrating suspended state. `on_timeout`, `deadline`, and `resume_input_schema` in the Suspension envelope are inert.
- **Evidence**: Ticket `01KTPVTAZRJZTVRDCB4SP5M9QA`; `workflow.pypeline:116` (`"gate:suspend"` → `"halt"`); `planning.py:121` (`"gate_suspend": "halt"`); `pipeline/executor.py:222-224` (swallows unresolvable label)
- **Smallest correction**: Make `SUSPENDED` a first-class executor terminal exit distinct from `halt`. Wire `SuspensionRecord`/`SuspensionCursor` (`kernel/suspension.py`) into the neutral executor. Honor `deadline`/`on_timeout`. Provide resume entrypoint that rehydrates suspended pipeline state.
- **Exact evidence**: `arnold/kernel/suspension.py:18-24` (SuspensionState exists), `arnold/pipeline/native/runtime.py:744-854` (no SUSPENDED in outcome kinds), `arnold_pipelines/megaplan/workflows/planning.py:121`

## 3. Firm Position

**The system has architectural coherence at the substrate level but semantic fragmentation at the control level.** The native runtime (`run_native_pipeline`) is a clean sequential state machine with proper checkpoint/resume. The graph executor is a proper graph walker. The handlers are feature-complete for Megaplan's product needs. The auto-drive loop is battle-tested with stall detection, tier escalation, cost caps, and recovery.

**But the semantic path from `workflow.pypeline` to runtime behavior is fractured across four independent authorities:**

1. **The `.pypeline` source** declares topology, route bindings, and policy — but at runtime, none of it is directly enforced.
2. **`components.py`** carries `handler_ref`, `route_bindings`, `RUNTIME_BRANCH_VOCABULARY` — the actual dispatch metadata.
3. **`planning.py`** bridges lowered source and component metadata through alias tables — a compatibility layer masquerading as a compiler.
4. **`auto.py:drive()`** is the real runtime — it reads `state["current_state"]`, calls `workflow_next()`, and dispatches subprocess CLI commands.

**The North Star (`NORTHSTAR.md:5-15`) is correct**: final semantic authority must be `workflow.pypeline` + imported native subworkflows + declared policies. The current implementation is approximately 40% of the way there — the `.pypeline` has the right shape (branches, loops, `parallel_map`, tiebreaker calls), but the actual semantics are still in component metadata, handler-internal state mutation, and the auto-drive loop's special-case logic.

**The two CRITICAL gaps (suspension-not-primitive, double-route-brain) are architectural blockers for any caller that assumes the runtime contract matches the authored source.** The three HIGH gaps (hidden semantic completion, silent routing failure, typed seam not wired) are correctness hazards that will cause production debugging nightmares. The MEDIUM gaps are deferred-migration debt that the corrective epic (`megaplan-native-parity-corrective`) explicitly targets.
