## 2. Concrete False-Pass Mechanisms

### FP-1: Paperwork validator passes on self-authored evidence (CRITICAL)

**Path**: `scripts/validate_native_representation_conformance.py:707-1090`
**Path**: `scripts/generate_native_representation_evidence.py:40-57`

The validator (`validate_conformance_ledger`) checks:
1. `conformance.yaml` rows have correct schema, status labels, carrier types
2. `evidence.yaml` records have matching row IDs, SHA256 hashes that match current disk files
3. Paths exist on disk
4. Suffix constraints (`.pypeline` for `canonical_source`)

It does NOT:
- AST-inspect whether `workflow.pypeline` actually contains the semantics claimed
- Run any behavioral test
- Verify that `DECLARED_STEP_INTERFACES` with `handler_ref` isn't smuggling routing
- Check that imported `AUTHORING_*` constants from `components.py` aren't carrying semantics

**Reproduction**: Generate an evidence bundle from the conformance YAML, write a `workflow.pypeline` containing only `pass`, regenerate SHA hashes, update evidence.yaml. Validator passes.

**The `APPROVED_CARRIER_NAMES` allowlist** at `scripts/generate_native_representation_evidence.py:79-90` maps exactly 10 paths to names. Evidence records with any other `carrier_path` would be rejected, but the allowed paths are themselves the wrapper files.
