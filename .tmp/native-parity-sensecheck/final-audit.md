# Native Megaplan parity: hierarchical gap audit

**Audit date:** 2026-07-21  
**Checkout:** `304c44476738e191f957890c438c5833b7c249be` plus the current, dirty working tree  
**Mode:** read-only; no product, plan, test, documentation, or git state was changed  

## Verdict

**Materially misaligned.** The corrective plan and its seven active briefs largely understand the intended migration, but the implemented system still has the exact split-authority shape the NORTHSTAR forbids. The canonical `.pypeline` is a source-shaped representation, not the canonical executable semantic carrier:

1. `workflow.pypeline` imports component-backed `AUTHORING_*` steps and policies and embeds `handler_ref`, route-binding, topology-contract, and override-route dictionaries (`workflow.pypeline:14-34,81-385`).
2. Lowering sees the detailed authored graph, but `build_pipeline()` selects and reconstructs component-backed coarse steps, merges component metadata over lowered metadata, and rebuilds routes through component vocabulary (`workflows/planning.py:28-94,237-345,643-721`). A direct current-tree probe found **85 lowered steps → 14 canonical steps, 23 routes, 13 handler refs, and zero retained fanout policies**.
3. Runtime route choice is still derived from handler response strings, `components.py` route bindings, and hard-coded per-phase maps; an unrecognized gate response defaults to `gate:finalize` (`runtime/manifest_backend.py:173-189,227-320`).
4. Auto-drive executes a compatibility-projected `NativeProgram` whose phase functions call CLI `COMMAND_HANDLERS`, while the status loop continues to derive `next_step` and implement its own retries, escalation, and resume (`_compatibility.py:101-115,173-267`; `auto.py:628-738,3661-3669,4329-4432,4534-5078`).
5. The conformance closeout can accept claims without checking their semantics. The generator turns declared `implemented` rows into whole-file hash records; the validator validates hashes and shapes, not the claimed AST or behavior. It ignores red auxiliary checks. The published report consequently says all 31 rows are implemented while explicitly recording `passed=False` for compatibility quarantine and deletion (`conformance-report.md:24-67`).

The practical consequence is stronger than “some work remains.” Editing the visible source can leave canonical runtime behavior unchanged; editing a handler, component policy, route backend, state table, CLI handler, or auto-drive path can change product behavior without a corresponding authored-source change. Native parity is therefore not presently established.

## Method and evidence discipline

Five independent Hermes reviewers were fanned out over non-overlapping lenses: end-state inventory, plan/brief coverage, current topology, runtime/control semantics, and adversarial conformance. Each inspected the repository directly. Their raw reports are retained beside this audit in `reviewer-results/`. I reconciled disagreements against the primary sources and current checkout, and used git history to distinguish the seven auto-publish snapshots from later/current code.

Two reviewer conclusions were corrected during reconciliation:

- The corrective chain **did execute**: the seven auto-publish commits are `0e2f024b21`, `c9da330a9b`, `014098a6f8`, `6ab12427dd`, `5366d5c488`, `3acfa81110`, and `57555c82b7`. A later integration commit, `fc98a216b9`, landed additional S7-era source/evidence work.
- Dynamic `parallel_map` authoring and lowering **do exist** (`source_compiler.py:3662-3810,5326-5358`). The actual gap is that the canonical builder discards those fanout policies, and the generic execution router only treats a node as fanout when it has a static non-`None` width (`execution/routing.py:59-63,383-420`).

The blocker is canonical retention/runtime materialization, not total absence.
- **Native cursor/checkpoint substrate exists.** The generic native runtime has structured cursor/path machinery capable of genuine state restoration. The gap is that canonical Megaplan suspension/fanout is not wired through it consistently.
- **The source does expose several intended names and coarse branches.** Critique/execute/review maps, a critique loop, four tiebreaker calls and typed gate/review/override branches are visible (`workflow.pypeline:388-754`). They are valuable migration scaffolding; they are not yet authoritative.

- **Git history preserves the distinction between sprint publishes and later integration.** There is enough provenance to avoid pretending the S2 or S7 publish itself delivered the later current source.

## Final position

Do not claim native Megaplan parity from the current tree, generated report, seven auto-publish commits, or existing green subsets. The strongest safe claim is: **the repository has a substantial native-shaped authoring prototype and useful typed/compiler/runtime substrate, while canonical product semantics still execute through a component/handler/state/CLI/auto compatibility architecture and conformance can false-pass that fact.**

Parity becomes credible only when (1) canonical runtime is demonstrably a semantics-preserving execution of the authored source, (2) the old carriers are behaviorally inert or deleted, and (3) the proof system runs the real paths and makes every red auxiliary gate fatal.
