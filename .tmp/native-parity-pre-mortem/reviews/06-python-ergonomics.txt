## 2. Ceremony, Duplicated Declarations, and Identity Plumbing

### 2.1 Triple Topology Representation (THE critical finding)

The **same workflow topology** is encoded in three independent representations that must stay synchronized:

| Representation | Location | Lines | Nature |
|---|---|---|---|
| Authored Python | `workflow.pypeline:388-754` | 367 | Human-readable, Python-shaped |
| State-machine dict | `_core/workflow_data.py:45-92` | 48 | `Transition` dataclass list per state |
| Realized graph | `_core/topology.py:234-248` | 15 | `build_topology()` → `Graph(edges=...)` |

Plus:
- `workflows/planning.py:110-139` — `_LOWERED_STEP_ID_ALIASES` (39 alias mappings) and `_ROUTE_LABEL_BY_TRANSITION_ID` (duplicate route labels)
- `_core/workflow.py:170-185` — `_resolve_overrides` rewrites transitions per robustness+creative
- `_core/workflow.py:273-298` — `_workflow_for_robustness` merges override layers

**Each edit to the workflow graph requires touching at minimum 3 files.** The workflow_data `WORKFLOW` dict is the runtime authority for handler dispatch; `workflow.pypeline` is the authoring authority; `topology.py` mediates between them. They cannot drift because tests enforce parity (`test_pipeline_golden.py:100-155`), but they are conceptually redundant.

### 2.2 Four-Domain Identity Plumbing

Every step carries identity through four separate namespaces:

1. **`workflow.pypeline` step ID** — e.g. `"critique-fanout"`, `"execute-batches"`, `"review-fan-in"` (lowered IDs)
2. **Canonical step ID** — e.g. `"critique"`, `"execute"`, `"review"` (public API IDs, mapped via `_LOWERED_STEP_ID_ALIASES`)
3. **`kind` string** — e.g. `"megaplan:critique"` (used in `Pipeline` DSL)
4. **`stable_id`** — e.g. `"megaplan.native.critique.v1"` (in `native_interfaces.py:121-136`)

The `_canonical_step_id` function (`workflows/planning.py:204-205`) and `_topology_step_id` (`workflows/planning.py:208-217`) use suffix-based heuristics (`"review" in step_id`, `endswith("-execute-batches")`) that are fragile. If a new lowered ID like `"security-audit-review"` were introduced, it would silently map to `"review"`.

**`native_interfaces.py`** (413 lines) is a *pure metadata module* with zero runtime logic. Every `NativeInterface` duplicates handler refs already in `workflow.pypeline`'s `DECLARED_STEP_INTERFACES` and adds `legacy_aliases`. This is four-domain identity: (step_id, kind, stable_id, handler_ref).

### 2.3 Policy Noise — Over-Granular Typed Constructs

`execute/policy.py` (1085 lines) introduces typed enums (`ExecuteEntryRoute`, `ApprovalOutcome`, `NoReviewTerminalOutcome`, `TierRouteOutcome`, `BlockedRetryOutcome`, `NextExecuteTransition`) that are *immediately translated back* to legacy `CliError` raises and string-keyed response fields in the handler. The handler (`handlers/execute.py:304-345`) imports both the typed policy AND maps them to legacy constructs:

```python
# handlers/execute.py:197-215

    NextExecuteTransition.EXECUTE: "execute",
    NextExecuteTransition.REVIEW: "review",
```

This is a **translation layer that adds lines without removing the legacy surface**. A similar pattern exists in `handlers/gate.py` where `_build_gate_route_signal` and `_critique_terminate_branch` carry their own typed termination logic.

### 2.4 Override Action Matrix — Duplicated Authority

The 11 override actions are declared in **three separate locations**:

1. `workflow.pypeline:36-79` — `DECLARED_OVERRIDE_OUTCOME_TARGETS` and `DECLARED_OVERRIDE_POLICY_ROUTES`
2. `workflows/override_matrix.py:54-151` — `_DECLARED_OVERRIDE_AUTHORITY` mapping with `family`, `route_signal`, `dispatch_surface`, `control_routed`

## 3. Opaque Helpers Likely to Drive Bypasses

### 3.1 `_transition_matches` (8 condition predicates)

`_core/workflow.py:301-331` — The 8 conditions (`gate_unset`, `gate_iterate`, `gate_escalate`, `gate_tiebreaker`, `gate_proceed_agent_availability_blocked`, `gate_proceed_blocked`, `gate_proceed`, `always`) are string-matched against `state["last_gate"]["recommendation"]`. The semantics require reading the implementation:

- `gate_proceed_agent_availability_blocked` checks that recommendation is PROCEED, passed is False, AND the only failed preflights are `claude_available`/`codex_available`. This is **business logic encoded as a string predicate name**.
- The condition names don't appear in `workflow.pypeline` — they're runtime-only constructs bridging the handler and the state machine.

### 3.2 `_resolve_overrides` creative-mode rewrite

`_core/workflow.py:170-185` — When `creative=True` and robustness is `light`, transitions are rewritten to skip critique entirely. This has no counterpart in `workflow.pypeline` and would surprise anyone tracing the authored source.

### 3.3 `_critique_terminate_branch` hidden state mutation

`handlers/gate.py:466-501` — Sets `state["current_state"] = STATE_BLOCKED` to force `workflow_next` to return `[]`, preventing the auto-loop from re-deriving "revise". The comment at line 473-476 acknowledges this is a workaround: "the auto/chain loop is STATUS-DRIVEN...termination MUST be expressed in state, not just the return tuple, or the loop re-derives revise and spins forever (P0)."

### 3.4 `_LIGHT_CRITIQUE_CAP = 2`

`handlers/gate.py:342` — A hardcoded cap that overrides the configured `max_critique_iterations`. Light robustness caps at 2 iterations regardless of config. The comment explains it but the constant is buried in gate.py, not in a policy module.

## 4. Separating Justified Compression from Dangerous Hiding

### Justified Semantic Compression

| Mechanism | Why justified |
|---|---|
| `parallel_map(id=..., items=..., step=..., reducer=..., path_template=...)` | Encapsulates fanout/fanin topology with reducer semantics. One call expresses what would otherwise be a loop + barrier + join. |
| `loop(policy=..., reentry_id=...)` | Captures bounded-cycle semantics at the authoring level. Without it, authors would need to manually write `while` + counter + exit condition. |
| `@phase` decorator with `produces`/`consumes` port declarations | Enables the native compiler to verify port connectivity statically. |
| `StrEnum` outcome classes (`GateOutcome`, `ReviewOutcome`) | Provides IDE autocomplete, exhaustiveness checking, and import-time parity with `RUNTIME_BRANCH_VOCABULARY`. |
| `@workflow(id=..., version=..., policy=...)` | Single decorator captures pipeline identity, versioning, and default policy. |

### Dangerous Hiding

| Mechanism | Risk |
|---|---|
| `_transition_matches` string predicates | The 8 condition names encode business logic inaccessible from the authored source. An author adding a gate outcome has no visibility into these. |
| `_LOWERED_STEP_ID_ALIASES` suffix heuristics | `"review" in step_id` is a time-bomb. A step named `"preview_draft"` would silently match. |
| `_critique_terminate_branch` state mutation | Mutating `current_state` to `STATE_BLOCKED` to prevent loop spin is a side-channel. The authored source has no `blocked` terminal in the critique loop. |
| `WORKFLOW` dict + `_ROBUSTNESS_OVERRIDES` | The runtime state machine and the authored `workflow.pypeline` express the same topology differently. An author reading only `workflow.pypeline` would not discover that `light` robustness removes the review step or that `bare` removes critique entirely. |
| `_resolve_overrides` creative flag | Creative mode silently rewrites transitions. The authored source doesn't express "if creative and light, skip critique." |

## 9. Illustrative API Sketch (Target State)

```python
# workflow.pypeline — the single source of truth
from arnold.workflow.authoring import loop, workflow, parallel_map, decision, effect
from arnold_pipelines.megaplan.outcomes import GateOutcome, ReviewOutcome, OverrideOutcome, TiebreakerOutcome

# Robustness is a policy overlay, not a parallel topology
@workflow(id="megaplan", version="m5", policy=DEFAULT_POLICY)
@robustness("light", skip=["review"])
@robustness("bare", skip=["critique", "review"])
def planning_workflow(brief: str) -> None:
    prep_signal = step.prep(id="prep", brief=brief)
    plan_payload = step.plan(id="plan", prep_payload=prep_signal)

    loop(policy=REVISE_LOOP_POLICY, reentry_id="critique")
    while True:
        critique_payload = parallel_map(
            id="critique",
            items=policy.critique_lenses(),
            step=CRITIQUE_PANEL,
            reducer=step.critique,
            path_template="critique/{item_id}",
        )
        match step.gate(id="gate", critique_payload=critique_payload):
            case GateOutcome.PROCEED:
                _execute_and_review()
            case GateOutcome.ITERATE:
                step.revise(id="revise", gate_payload=...)
            case GateOutcome.TIEBREAKER:
                _run_tiebreaker()
            case GateOutcome.ESCALATE:
                match step.override(id="override", gate_payload=...):
                    case OverrideOutcome.ABORT:
                        step.halt(id="halt")
                    case OverrideOutcome.FORCE_PROCEED:
                        _execute_and_review()
                    case OverrideOutcome.REPLAN:
                        step.revise(id="revise", gate_payload=...)
            case GateOutcome.ABORT | GateOutcome.SUSPEND:
                step.halt(id="halt")

def _execute_and_review():
    """Extracted helper — eliminates 200+ lines of duplicated if/elif chains."""
    step.finalize(id="finalize")
    execute_payload = parallel_map(
        id="execute",
        items=policy.execute_batches(),
        step=EXECUTE_BATCH,
        reducer=step.execute,
        path_template="execute/{index}",
    )
    match parallel_map(
        id="review",
        items=execute_payload,
        step=REVIEW_PANEL,
        reducer=step.review,
        path_template="review/{item_id}",
    ):
        case ReviewOutcome.PASS:
            effect.notify(channel="slack", message="Review passed")
            step.halt(id="halt")
        case ReviewOutcome.REWORK:
            _execute_and_review()  # recursive rework — fresh session enforced by policy
        case ReviewOutcome.BLOCKED:
            step.override(id="override")
        case ReviewOutcome.DEFERRED_HUMAN:
            step.halt(id="halt", reason="deferred_human")
```

## 12. Summary Judgment

The authoring surface (`workflow.pypeline`) is **good** — Python-shaped, enum-typed, with explicit `parallel_map` and `loop` primitives. The problem is that the rest of the system **doesn't trust it**. Instead of generating the runtime machinery from the authored source, three parallel representations are hand-maintained and parity-tested against each other.

The complexity budget is exceeded by ~2x: `components.py` at 2977 lines is 6x the target; `handlers/override.py` at 1944 and `handlers/review.py` at 1854 are 2.5x. The four-domain identity plumbing (step_id, kind, stable_id, handler_ref) adds friction to every edit without adding expressive power.

The single most impactful change: **generate the `WORKFLOW` dict and `build_topology()` graph from the lowered pipeline**. This eliminates ~400 lines of hand-maintained topology data, removes the parity-test tax, and makes `workflow.pypeline` the undisputed source of truth.
