# Isolated Review 4 — Future Workflow Author and Extension Test

## Architecture Summary

The system has **three authoring surfaces** with overlapping concerns:

| Surface | Location | Role |
|---|---|---|
| **Native decorators + compiler** | `arnold/pipeline/native/{decorators,compiler,ir,runtime}.py` | Canonical Python-shaped authoring: `@pipeline`, `@phase`, `@decision` → AST compile → `NativeProgram` → `run_native_pipeline` |
| **Explicit-node DSL** | `arnold/workflow/{dsl,compiler}.py` | Declarative `Pipeline(steps=..., routes=...)` → `WorkflowManifest` — no decisions, no effects, no human gates |
| **Megaplan substrate (M11, locked)** | `arnold_pipelines/megaplan/` | Handler-based state-machine, auto-driver, recovery policy, override matrix, gate checks |

The **evidence_pack** workflow (`arnold_pipelines/evidence_pack/`) demonstrates dual registration: a native program (`native.py:299-325`) **and** an independently-built projected shell (`pipeline.py:85-164`), with `build_pipeline()` attaching the native program to the shell at `pipeline.py:167-184`. This dual-registration pattern is the root of most extension ambiguity.

## Semantic-Authority Risks vs. Ergonomic Polish

### Semantic-authority risks (threaten the correctness of audit, topology, replay)

1. **Override has no native topology** — The most severe gap. Overrides affect control flow (force-proceed skips gate, abort terminates, replan rewinds) but have zero representation in `NativeProgram`, `NativeTopology`, or the compiler. Any audit of "what can this workflow do?" is incomplete without reading megaplan handler code.

2. **Human gates can bypass `@decision`** — `@phase` functions can emit `Suspension(kind="human")` directly (as `HumanReviewStep.run()` does). The runtime enters the phase-suspended path instead of the human-gate path, meaning the `@decision`'s `choices`, `override_routes`, `resume_input_schema`, and `artifact_stage` are never consulted. The compiler doesn't detect this.

3. **Handler outcomes drift from decision vocabulary** — The native `@decision(vocabulary={"fail", "pass"})` is the declared control surface. But megaplan handlers can emit outcomes that the auto-driver processes without any vocabulary check. A `verdict_is_fail` decision returning `"needs_review"` would compile fine but break at runtime — or worse, be silently added as a handler path.

4. **Effects undeclared on phases are invisible to reconcile/replay** — The native runtime's `_reconcile_resumed_effect` at `runtime.py:1118` only activates for phases with `operation` declared. A phase that writes files but omits `operation="file_write"` has no reconcile protection on resume — the runtime will re-execute it.

### Ergonomic polish (friction, not correctness)

1. **Dual registration burden** — The evidence_pack's `pipeline.py` builds a projected shell independently of `native.py`. Every new phase must be added in THREE places: the `@phase` in `native.py`, the `parallel()` branch list, AND the `validator_step_names` tuple in `pipeline.py`. The graph projection at `graph_projection.py` can derive stages from the native program, but the evidence pack doesn't use it — it rebuilds the shell by hand.

2. **No `@phase` → `Step` auto-registration** — Adding a `@phase` function doesn't automatically register it in the projected shell or the handler dispatch. A developer must remember to add it to the parallel block AND the projected stage list.

3. **Retry taxonomy mismatch** — The native runtime has `max_attempts: int` (a single number) while megaplan's `RecoveryPolicy` has `retry_fresh | retry_transient | escalate | halt` with per-budget counters. These don't map naturally.

4. **Effect taxonomy needs synchronized extension** — Adding an operation requires edits to `effect_taxonomy.py` (the literal), the `@phase` decorator call site, any reconcile table entries in `reconcile.py`, AND any handler code in megaplan. Four synchronized edits for one effect.

5. **The `native.py` generator syntax is discoverable only by example** — The `@pipeline`-decorated generator with `yield` and `if`/`else` (`evidence_pack_native` at `native.py:299-325`) is the only complete example in the repository. There's no tutorial or template generator.
