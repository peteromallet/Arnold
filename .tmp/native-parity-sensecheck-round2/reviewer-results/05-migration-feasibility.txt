## 3. Deletion-Order Hazards and Compatibility Escape Hatches (Ranked)

### 🔴 Hazard 1: `manifest_backend.py` survives as handler-return-string-to-edge translator

**Evidence:** manifest_backend.py:72–84 defines `HANDLER_NODE_IDS` — every product node name. Lines 63–100 override `_execute_node_payload` to dispatch to handlers and translate their `StepResponse` return values (`next_step`, `route_signal`, `recommendation`, `review_verdict`, `override_action`) into `NodeOutcome` branch edges. This is the *consumer* of handler route strings — even after `components.py` route_bindings are deleted, this backend still interprets whatever the handler returns as a routing decision. No sprint brief names this file for quarantine or replacement.

**Mitigation needed:** Add a sprint-3 or sprint-4 task: "Replace `manifest_backend._execute_node_payload` branch-edge translation with canonical lowered topology routing; prove mutation to handler return values cannot change the trace."

### 🔴 Hazard 2: `_core/workflow_data.py:45–92` + `_ROBUSTNESS_OVERRIDES` (lines 95–126)

**Evidence:** `WORKFLOW` dict maps `STATE_CRITIQUED → gate/revise/tiebreaker/override` transitions keyed by condition strings like `"gate_iterate"`, `"gate_tiebreaker"`, `"gate_escalate"`. `_ROBUSTNESS_OVERRIDES` allows `"bare"` to skip critique entirely (`STATE_INITIALIZED → plan → STATE_PLANNED`). This is a **complete parallel state machine** that can still route independently. No sprint brief mentions deleting or freezing this table.

**Mitigation needed:** Sprint 3 must hard-quarantine the `WORKFLOW` dict — either delete its write path or add a `FROZEN_SINCE` epoch check that raises if any code reads it as route authority. Add `_ROBUSTNESS_OVERRIDES` to the same quarantine.

### 🔴 Hazard 3: `auto.py` (5808 lines) — "reduce to event consumption" is underspecified

**Evidence:** auto.py:1–15 admits the driver reads `status`, derives `next_step`, and applies defaults (ESCALATE→force-proceed, stall detection). The S6 brief (s6-brief.md:26–30) says "auto-drive may not derive product route, retry/cap policy, model choice, resume, completion, cancellation, publication, or delivery from state/status" — but provides no concrete mechanism to enforce this. Without a clear `EVENT_CONSUMER_ONLY` wrapper or delegation gate, auto.py's existing `next_step` derivation remains load-bearing.

**Mitigation needed:** Sprint 6 must add an explicit `AUTO_MODE = "consumer" | "legacy"` flag with CI enforcement that `consumer` mode cannot call `next_step` derivation or handler dispatch. Old `auto.py` behavior must be gated behind `legacy` and excluded from S7 proof.

## 5. Feasible/Sound Migration Choices

### Choice 1 (Recommended): Add a mid-plan `S3.5 — Carrier Quarantine Sprint`

**What:** A narrow 1-week sprint after S3 that quarantines the three surviving alternate brains — `manifest_backend.py`, `_core/workflow_data.py`, and `auto.py` route derivation — before S4 begins building tiebreaker/finalize on top of the corrected front-half foundation.

**Why:** S3 deletes front-half component routes and handler route strings, but `manifest_backend.py` still interprets handler return values, `_core/workflow_data.py` still has a parallel state machine, and `auto.py` still derives `next_step`. Building S4–S6 on a foundation that looks corrected but still has live route spoofing underneath repeats the false-pass pattern. A dedicated quarantine sprint breaks this dependency.

**Risk:** One week of no product-facing progress. Mitigation: quarantine means "freeze and guard" not "rewrite" — add runtime guards and negative tests, not new execution paths.

### Choice 2 (Alternate): Enforce per-sprint carrier deletion gates in chain.yaml

**What:** Add per-milestone `validate` blocks to the chain.yaml that prove specific carriers are dead before the next milestone starts. The current schema (corrective-plan.md:474–489) admits only `final_conformance_gate` on the final milestone, but generic per-milestone validators could be added.

**Why:** Stronger than prose acceptance criteria. If the chain runner could execute `python -m arnold_pipelines.megaplan.verify_carrier_dead manifest_backend` after S3, the subsequent milestones cannot close on a false foundation.

**Risk:** Chain schema changes are "useful harness follow-up but not duplicated inside this product epic" (corrective-plan.md:489). However, without schema enforcement, the plan relies entirely on brief-acceptance-criteria discipline, which was insufficient in the prior native-composition pass.

### Choice 3 (Fallback): Accept the three survivors as "non-authoritative projections"

**What:** Declare `manifest_backend.py`, `_core/workflow_data.py`, and `auto.py` as non-authoritative projections — like the status/watchdog projections already defined. Prove in S6 that they consume but do not decide.

**Why:** Less work than quarantine. The oracle synthesis (oracle-synthesis.md:149–170) says "Adapters that translate data may remain. Adapters that translate decisions must die." If the three modules are proven to be pure data adapters downstream of canonical source, they can survive.

**Risk:** The oracle also says "Drift factories unless deleted or quarantined" (line 158). `manifest_backend._execute_node_payload` is a decision translator — it turns handler strings into route edges. Calling it a "projection" after it has already decided product routes would repeat the false-pass error. This choice is sound only if every decision path in these modules is replaced with a canonical-source-derived lookup. That is equivalent to quarantine in effort.

### Choice 4 (Minimum Viable): Add the six text amendments above and proceed

**What:** Merge the six amendments into the briefs, ensure S2 delivers `foreach`/`parallel_map` source syntax, and rely on per-sprint acceptance criteria to catch survivors.

**Why:** Lowest overhead. The corrective plan already identifies the false-pass risks. The amendments tighten the existing acceptance criteria without restructuring the sprint order.

**Risk:** Without chain-schema enforcement or a dedicated quarantine sprint, nothing mechanically prevents a sprint from closing while `manifest_backend.py` still routes through handler strings. The S7 final conformance gate is the only blocking gate — and by then, the entire epic's structure depends on that survivor being dead. Late discovery means replan or late quarantine, which is the same risk the prior native-composition work encountered at M8/M9 (corrective-plan.md:58–60: "Intermediate M8/M9 receipts... do not satisfy admission").

**Take Choice 1 (S3.5 Carrier Quarantine) + Amendments A–G.** The plan is structurally sound — the s1–s7 briefs correctly identify sequential dependency, the four-domain identity model, the need to relocate WBC producers first, and the closure anti-patterns. But the three surviving alternate brains (`manifest_backend.py`, `_core/workflow_data.py`, `auto.py`) are not individually named for quarantine in any sprint, and dynamic `foreach`/`parallel_map` source syntax is not required in S2's acceptance criteria. The amendments close these gaps; the S3.5 sprint makes closure mechanically enforced rather than prose-dependent.
