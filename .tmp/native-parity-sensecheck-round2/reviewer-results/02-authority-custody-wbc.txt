## 1. Decisive Lens Verdict

**The seven-sprint plan is architecturally sound in its articulated contract but the current working tree is a material regression from that contract.** The canonical authored source (`workflow.pypeline`) is the exact forbidden component-call skeleton that NORTHSTAR, the corrective plan, and all seven active briefs explicitly prohibit. The lowering path sees 85 detailed authored nodes and collapses them into 14 component-identified steps where component metadata overrides lowered metadata on merge (`planning.py:669`). Dynamic fanout policies are lowered as `width=None`, then discarded by the canonical builder, and the generic router only activates fanout for non-`None` width. The consequence is that editing the visible `workflow.pypeline` source can leave canonical runtime behavior unchanged, while editing a handler, component policy, or the route backend can change product behavior without an authored-source change.

**The four-identity coordinate system is defined in contract documents but collapsed in code.** The `workflow.pypeline` uses `execute/{index}` path templates (not task ID + batch identity), `SUSPEND` routes to terminal `HALT` (not durable reentry), and tiebreaker researcher/challenger are sequential calls sharing a handler (`workflow.pypeline:472-488`), not parallel children. WBC producers remain attached to handler names; the custody substrate (M11) has not yet been completed in this tree. The conformance generator can iterate rows already labeled `implemented` and manufacture supporting hash records without semantic or behavioral proof; auxiliary red checks are generated but not made blocking.

**Verdict: Native Parity is not presently established.** The corrective plan and briefs correctly diagnose the problem and specify the solution, but the seven sprints have produced auto-published commits that do not satisfy their own exit gates. The strongest safe claim is that the repository has substantial native-shaped authoring/compiler/runtime substrate, while canonical product semantics still execute through the component/handler/state/CLI/auto compatibility architecture and conformance can false-pass that fact.

## 3. Ranked Failure Routes

### FR-1: The 85→14 Collapse Makes Authored Source Decorative

**Severity:** Critical | **Confidence:** Very High | **Consequence:** Editing `workflow.pypeline` leaves runtime behavior unchanged; editing a handler changes product behavior without source change

The lowering path in `source_compiler.py:3662-3810` correctly parses 85 detailed nodes with dynamic fanout policies, reducer references, and path templates. But `build_pipeline()` in `planning.py:695-721` calls `_canonical_steps()` which filters through `PIPELINE_STEP_COMPONENTS` — exactly 14 component identities (`planning.py:650`). The merge at `planning.py:669` (`{**lowered.metadata, **canonical.metadata}`) makes component metadata win over lowered metadata. Dynamic fanout policies are discarded because the canonical builder produces no nodes with `FanoutPolicy`. The generic router at `execution/routing.py:59-63` only treats a node as fanout when it has a non-`None` static width.

**Minimal plan amendment:** Make `_canonical_steps()` return the lowered graph directly (or a semantics-preserving normalized graph) without filtering through component IDs. Add a blocking assertion that lowered node count equals canonical node count and that every `FanoutPolicy` in the lowered graph is retained. This is a one-function change in `planning.py` with cascading test implications; it must be the first patch before any other migration work.

### FR-2: Circular Conformance Generator Can False-Pass Semantics

**Severity:** Critical | **Confidence:** Very High | **Consequence:** The system can claim "implemented" for every row while the actual semantic carrier is the forbidden component architecture

The evidence generator iterates rows already labeled `implemented` and manufactures `source_checker` hash records that reference whole-file spans. The validator checks path existence and SHA-256, not the claimed semantic construct or its authority. Auxiliary compatibility/purity/deletion checks are generated but omitted from the validator's `EvidenceBundle` data model — red checks do not block `implemented` status. The published conformance report says all 31 rows are implemented while explicitly recording `passed=False` for compatibility quarantine and deletion.

**Minimal plan amendment:** Replace the self-declared evidence loop. The generator must consume signed checker results (rule ID, precise AST span, negative mutation result, executable command/version) and package them, never create them. Extend the validator schema so every required auxiliary gate must be present with `passed is True`. Reject unknown or unconsumed evidence sections. This is a generator-rewrite + validator-schema change, not a one-line fix.

### FR-3: Forgotten Prerequisite — Custody M11 Does Not Exist

**Severity:** Critical | **Confidence:** Very High | **Consequence:** The entire authority/custody/WBC adoption plan has no substrate to bind to; seven sprints would produce parallel stores and enforcement

The custody-overlap-audit confirms: M9 is active with a dirty working tree, M10 and M11 have not begun. The remote checkout is provenance-divergent (M8A auto-publish carries a reconstructed tree without M6A/M7 merges as ancestors). `action_validator.py`, `run_authority/contracts.py`, `execution_attempt_ledger.py` — none exist in the current tree. The chain's prerequisite mechanism (`chain.yaml:9: require_manifest: true`) cannot validate a manifest that does not exist. If the seven sprints proceed, they will inevitably create parallel grant/lease/attempt stores because the admitted substrate is absent.

**Minimal plan amendment:** This is a sequencing fix, not a design fix. The chain must not start. There is nothing to amend in Native Parity except the launch precondition — it must wait for a clean, accepted M11 revision with a valid completion manifest. If the organization needs forward progress on Native Parity before M11 lands, it must be scoped as substrate-neutral authoring work (typed outcomes, control primitives, compiler improvements) that explicitly does not claim custody adoption.

`workflow.pypeline:14-34` imports `AUTHORING_PREP`, `AUTHORING_PLAN`, `AUTHORING_CRITIQUE`, `AUTHORING_GATE`, `AUTHORING_REVISE`, `AUTHORING_FINALIZE`, `AUTHORING_EXECUTE`, `AUTHORING_REVIEW`, `AUTHORING_HALT`, `AUTHORING_OVERRIDE`, and policy objects like `DEFAULT_POLICY`, `REVISE_LOOP_POLICY`, `CRITIQUE_PANEL_WORKFLOW`, etc. Lines 36-385 are dictionary declarations: `DECLARED_OVERRIDE_POLICY_ROUTES`, `DECLARED_OVERRIDE_OUTCOME_TARGETS`, `DECLARED_STEP_INTERFACES` (with `handler_ref` strings and `route_bindings`), and `DECLARED_WORKFLOW_TOPOLOGY_CONTRACTS`. ### FR-5: Tiebreaker Concurrency Is Specified But Not Required

**Severity:** High | **Confidence:** High | **Consequence:** A sequential tiebreaker implementation passes S3's exit gates while changing latency and failure semantics from the NORTHSTAR contract

**Minimal plan amendment:** Before S3 migration, make suspension produce a `SUSPEND` outcome with a persisted envelope containing capability, semantic reentry path, and WBC suspend lineage. Wire the native cursor machinery to materialize that envelope. Then migrate one gate at a time. Add kill/restart tests for every gate.

### FR-7: Proof Scenarios Are Never Executed

**Severity:** High | **Confidence:** Very High | **Consequence:** Split-outcome behavior claims have no runtime evidence; the system can claim `implemented` for paths that crash, hang, or route differently

The scenario test at `test_final_conformance_scenarios.py:31-113` validates module/case names, file paths, and hashes — it does not execute the cases or compare observed outcomes. The generator at `generator:1450-1604` records scenario metadata without running them. This means every branch (clarification, critique retry/fallback, every gate outcome, every tiebreaker decision, finalize error, approval allow/deny, DAG partial/block/cancel, review retry/rework/cap/human, every override action) is claimed without behavioral verification.

**Minimal plan amendment:** Run each scenario case in a clean subprocess, capture exit code/result/trace, and validate the exact observed route sequence against the expected semantic path. Make scenario execution part of the blocking validator, not a shape/path/hash check.

### Genuinely missing Native Parity integration (not M11's responsibility):

1. **Producer relocation from handlers to canonical nodes.** M11's M8 added WBC evidence around existing handlers. Native Parity must move producer identity to lowered node/child paths as handlers are demoted. This is Native Parity's responsibility and is not started.

2. **Four-domain identity mapping.** M11 distinguishes RA subject attempt, WBC execution attempt, and Custody lease — but the mapping to semantic node/child path is Native Parity's topology concern. No generated mapping exists in the current tree.

6. **Typed outcomes as runtime boundary.** M11 provides the WBC attempt schema; Native Parity must make handler return typed outcomes that the runtime consumes, not raw routing strings. `outcomes.py` has the types but `manifest_backend.py` still consumes handler route-signal strings.

9. **Conformance generator rewrite.** M11's proof framework will produce content-addressed receipts. Native Parity must replace the self-declared evidence loop with genuine checker/runtime receipts. This is a Native Parity proof concern, not M11's generic framework.

10. **Tiebreaker parallelism, fresh-session semantics, config-change reentry, per-item fanout policy.** These are all topology-specific concerns that M11's generic contracts do not address. They are Native Parity's responsibility and are underspecified or missing from the current implementation.

## 5. Sound Composition Choices

Several structural decisions in the plan and current substrate are correct and should be preserved:

1. **The NORTHSTAR's conjunctive action rule** (`current RA grant + fence AND current Custody lease + epoch AND exact-version WBC evidence`) is precise and composable. It prevents any single contract from becoming a universal authority. The custody-overlap-audit confirms the remote custody decisions encode this identically.

2. **The four-domain identity separation** (semantic node/child, RA subject attempt, Custody target/lease, WBC execution attempt) is the correct defense against identity collapse. Even though it is not yet implemented, the contract prevents a generic `attempt_id` from silently merging permission, ownership, evidence, and topology.

3. **The "WBC is never permission, lease is never permission" discipline** is non-negotiable and correctly stated in every document. The custody-overlap-audit confirms the remote custody decision record states this identically. This invariant must survive all seven sprints.

4. **The decomposition of pure phase bodies vs. topology-owning constructs** (`megaplan-native-parity-corrective-plan.md:134-158`) correctly identifies parsing, serialization, prompt construction, normalization, validation, lens selection, result merging, and ready-batch calculation as permissible phase internals, while routing, suspension, retry/cap/model policy, fanout topology, and checkpoint identity must be top-level. This boundary is the right one.

5. **The chain's `require_manifest: true` prerequisite** on Custody M11 (`chain.yaml:7-9`) is the correct gating mechanism. The defect is that M11 does not yet exist, not that the gating mechanism is wrong.

6. **The existing typed outcome infrastructure** (`outcomes.py:19-227`) provides closed `StrEnum` vocabularies for `GateOutcome`, `ReviewOutcome`, `TiebreakerOutcome`, and `OverrideOutcome`. This is sound groundwork even though raw handler strings still steer runtime.

7. **The `source_compiler.py` dynamic `parallel_map` parsing** (`source_compiler.py:3662-3810`) correctly validates item references, reducer references, and path templates with coordinate variables. The gap is retention and runtime activation, not parsing absence. This is fixable without compiler redesign.

8. **The native cursor/checkpoint substrate** (`arnold/pipeline/native/checkpoint`) with `classify_resume_cursor`, `read_native_cursor`, and `NativeCursorCorruptError` exists and is used by `evidence-pack` pipelines. The gap is wiring canonical Megaplan suspension to this machinery, not inventing it.

9. **The NORTHSTAR's "semantic compression without erasure" principle** (`NORTHSTAR.md:60-73`) correctly distinguishes between reducing visible steps through typed abstractions (good) and hiding semantics in handlers/components (bad). The bounded-loop, dynamic-map/reducer, and human-suspension generalizations are the right abstractions.

10. **The custody-overlap-audit's amended sprint structure** (`custody-overlap-audit.md:132-199`) correctly integrates Custody M11 adoption into every sprint with dual semantic + custody-adoption gates. This is a sound refinement of the corrective plan that should be adopted when M11 lands.

**Bottom line:** The plan is directionally correct and the custody substrate is complementary, not overlapping. The current working tree has not executed the plan. Seven sprints have produced auto-published commits that do not satisfy their own exit gates. The failure mode is not ambiguity in the contracts — it is that delivery was allowed to substitute for verification, and the evidence system was allowed to substitute for behavior. The three critical fixes (collapse removal, evidence-gen rewrite, M11 sequencing) plus the four high-severity fixes (source skeleton rejection, tiebreaker parallelism, durable suspension, scenario execution) are the minimum viable path to credible parity.
