**Gap 1 — Dynamic-fanout full contract not gated (NR-03, NR-21)**
*Severity: High. Source: RR:849-866; FA:A-02; CP:358-460; S2:12-15,39-43.*

The representation report specifies seven properties of the dynamic map contract: runtime collection source, item schema, max workers, per-item retry/fallback, sequential fallback, reducer, and deterministic naming. S2 says "dynamic runtime map/reducer, sequential fallback, per-item retry/fallback, deterministic child naming" (`:13-14`) but the *semantic gate* only requires "Dynamic fanout works for runtime-sized collections and collision tests prove identity is semantic, not list-position-only" (`:39-41`). It does not gate the *full contract*—max workers, item schema declaration, and per-item policy are not called out as exit-criteria proof items.

**Amendment:** Add to S2's semantic gate: "The dynamic fanout lowerer retains and runtime-asserts: (a) collection source reference, (b) item schema, (c) max-workers, (d) per-item retry/fallback policy, (e) sequential fallback on worker failure, (f) reducer with deterministic input order, and (g) deterministic child naming from semantic coordinates. A mutation disabling any of these must fail the reference pipeline test." Apply the same clause to S4 (execute batches) and S5 (review checks) exit criteria.

**Target:** `briefs/s2-front-half-native-loop.md` semantic gate section; `briefs/s4-execute-dag-approval-resume.md` semantic gate; `briefs/s5-review-rework-finalize.md` semantic gate.

**Gap 2 — Gate child steps not enumerated (NR-04)**
*Severity: High. Source: RR:148-160,432-455; FA:A-04; S3:15-18.*

The report identifies six named gate child steps: build signals, call worker, normalize, validate flags, reprompt, persist debt. S3 says "gate signal construction, worker call, normalization, flag validation, one reprompt/downgrade...debt effect, and closed typed decision" (`:15-18`) in the product scope, but the semantic gate only requires "gate reprompt/downgrade" and "debt effect" (`:44-45`). A single opaque `AUTHORING_GATE` call could satisfy these if the reprompt and debt are technically reachable inside the handler.

**Amendment:** Add to S3's semantic gate: "Each of the six gate child steps (signal construction, worker call, normalization, flag validation, reprompt, debt persistence) is a separate named source construct or declared subphase. Deleting or mutating any one must change the canonical trace. A single opaque gate component call does not satisfy this gate."

**Target:** `briefs/s3-tiebreaker-replan-native.md` semantic gate section.
