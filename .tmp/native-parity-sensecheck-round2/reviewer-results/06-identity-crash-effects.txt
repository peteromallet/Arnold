# Lens 6 — Identity, Crash, Resume, and Effects Adversary Audit

## 1. Verdict

**FAIL with recoverable gaps.** The system has four clean identity *vocabularies* (authored semantic topology, Run Authority, WBC/boundary-contract, Custody) but **zero identity translation bridges** between them. The native runtime persists checkpoints *only at suspension points*, not after successful phase completion — meaning a crash between a completed external effect and the next suspension loses durable evidence. The RA resolver has no custody-leasing or WBC awareness, leaving stale-authority windows where a coordinator whose lease expired mid-run is still classified RUNNING. The WBC evidence vocabulary (`BoundaryContract`/`BoundaryReceipt`) is structurally sound but has no runtime integration — no effect ledger snapshot in the resume cursor, no contract-version guard at action time, and no conformance proof that receipts are idempotent across replays. The kernel `EffectLedger` provides intent-before-execution at-most-once semantics, but it is disconnected from the native runtime and the WBC receipt layer. Custody M11 is complete as a standalone lease primitive, but its fencing tokens are not validated at RA decision time or WBC action time.

The four coordinates *can* be sound, but they currently operate in separate identity spaces. An adversary with access to a stale custody workspace can replay phase completions across hosts, produce duplicate effects, and the system has no integrated cross-coordinate validation that would detect it.

## 3. Ranked Gaps

### Gap 1: Crash-after-external-effect, before-receipt → duplicate effect (CRITICAL)
- **Severity:** CRITICAL
- **Confidence:** HIGH
- **Consequence:** External effects (git pushes, PR creation, API calls) that complete but crash before the next suspension checkpoint will re-execute on replay. The `EffectLedger` prerecord pattern only prevents duplicates when the INTENT was written, but the native runtime only checkpoints at suspension points, not after each phase.
- **Evidence:** `runtime.py:1233` and `runtime.py:1526` — `persist_native_cursor` only called on suspension (`phase_suspended`, `human_gate`), not after successful phase completion. `effect_ledger.py:48-61` — prerecord requires intent event before execution. There is no integration between the native runtime and the effect ledger.
- **Minimum plan amendment:** Add a `checkpoint_after_phase` configuration to the native runtime that persists a cursor after every phase that declares external effects. Wire `EffectLedger.prerecord()` into phase execution so that INTENDED is durable before execution. Test: crash simulator that kills the process between effect execution and checkpoint, then verifies replay does not duplicate the effect.

### Gap 2: Identity translation between authored topology and WBC boundary (CRITICAL)
- **Severity:** CRITICAL
- **Confidence:** HIGH
- **Consequence:** The authored semantic node (`native.pc` + `stages` + `run_path`) has no mapping to a WBC `boundary_id`. A `BoundaryReceipt` references `boundary_id`/`workflow_id`/`row_id`, but the native cursor carries `stage`/`stages`/`stage_reentry_points`. There is no identity bridge. Conformance proofs cannot trace from an authored decision to its WBC evidence.
- **Evidence:** `checkpoint.py:11-37` — cursor shape has `native.pc`, `stages`, `stage_reentry_points`. `boundary_evidence.py:91-111` — `BoundaryContract` has `boundary_id`/`workflow_id`/`row_id`. No code maps between these spaces.
- **Minimum plan amendment:** Define a `TopologyToBoundaryMapping` that registers each `@phase`/`@decision` node name to a `boundary_id` at compile time. Include this mapping in the cursor. Validate at action time that the cursor's `boundary_id` matches the contract's expected `boundary_id`. Add to the `native-platform-followup/m6` final conformance gate a proof that every authored instruction has a corresponding boundary contract.

### Gap 3: RA resolver is custody-blind (HIGH)
- **Severity:** HIGH
- **Confidence:** HIGH
- **Consequence:** A coordinator whose lease was stolen continues to be classified RUNNING if its worker process is alive. The new lease holder sees the same RUNNING classification. Two coordinators can simultaneously believe they own the run.
- **Evidence:** `classifiers.py:277-351` — `ResolverContext.build()` consumes `chain_state`, `plan_state`, `tmux_process`, `needs_human`, `stale_evidence`, `repair_progress` — **no custody lease state**. `capacity_lease.py:35-48` — `StaleLeaseError` detects stale writes but the RA resolver never reads lease state.
- **Minimum plan amendment:** Add `custody_state` as a 7th evidence source in `resolve_run_state`. Define `CUSTODY_STALE_LEASE` classifier that fires when `fencing_token < last_token` and the worker is not live. Wire `CapacityLease` into the evidence normalization pipeline. Test: dual-coordinator scenario with lease expiry.

### Gap 4: No contract-version fence at WBC action time (HIGH)
- **Severity:** HIGH
- **Confidence:** MEDIUM
- **Consequence:** If a `BoundaryContract` version changes during a suspended run, the resume uses the new contract version without validation that the pre-suspension work satisfies the new contract. Receipts produced before the version change may become invalid.
- **Evidence:** `boundary_evidence.py:110` — `contract_version: str = "arnold.workflow.boundary_contract.v1"`. No version comparison logic in `BoundaryContract.__post_init__` or in any consumer. `resume.py:136` — `run_native_pipeline(build_native_program(), ...)` recompiles the program, which may embed a new contract version.
- **Minimum plan amendment:** Add `expected_contract_version` to the resume cursor. On resume, compare against current `BoundaryContract.contract_version`. If mismatched, quarantine the resume. Add `contract_version` to `BoundaryReceipt` validation: receipts from mismatched contract versions must be marked `SUPERSEDED`.

### Gap 5: Policy/model-route recompiled on resume, not snapshotted (HIGH)
- **Severity:** HIGH
- **Confidence:** HIGH
- **Consequence:** `resume_evidence_pack()` calls `build_native_program()` which recompiles the pipeline from source. If the source changed during suspension (model routing, timeout configuration, call-site policy), the resumed execution uses different semantics than the original run. The cursor carries `state` and `envelope` but not the compiled `NativeProgram` or policy snapshot.
- **Evidence:** `resume.py:136-143` — `run_native_pipeline(build_native_program(), ...)`. There is no program snapshot or hash in the cursor. The only hash check is `manifest_hash` comparison in `resume.py:migrate_legacy_resume()` for trust transitions.
- **Minimum plan amendment:** Compute a `program_content_hash` at initial compile time and store it in the cursor. On resume, validate that `build_native_program()` produces the same hash. If not, quarantine the resume with `TrustTransition(TRUST_UNKNOWN, TRUST_QUARANTINED_MANIFEST_MISMATCH)`. This leverages the existing `TrustTransition` infrastructure.

### Gap 6: Cross-host resume lacks custody validation (MEDIUM)
- **Severity:** MEDIUM
- **Confidence:** MEDIUM
- **Consequence:** When a pipeline is suspended on host A and resumed on host B, there is no validation that host B holds the custody lease. Host A may still hold the flock (if it didn't crash), leading to dual execution.
- **Evidence:** `resume.py:48-68` — `_load_resume_cursor` only checks cursor kind and validity. No `CapacityLease` acquisition or validation. `test_suspension.py:13-28` — test only validates suspension record round-trip, not custody integration.
- **Minimum plan amendment:** Add optional `require_custody_lease: bool = True` parameter to `resume_evidence_pack()`. If enabled, acquire the `CapacityLease` for the run's tenant before loading the cursor. If the lease cannot be acquired (stale or held by another host), fail the resume.

### Gap 7: Dynamic fanout has no authored topology (MEDIUM)
- **Severity:** MEDIUM
- **Confidence:** HIGH
- **Consequence:** Task batches and dynamic fanout are hidden inside handler code (`batch.py:2278`). They have no authored `@foreach`/`@parallel.map` topology, no per-child checkpoint, and no per-child WBC receipts. This means fanout children cannot be independently suspended, resumed, or validated.
- **Evidence:** `representation-report.md:194-205` — "Execution hides a substantial workflow... The large auto-execute loop is `handle_execute_auto_loop()`". `native.py:303-314` — only fixed `parallel()` is authored, not dynamic `foreach`. Planned in `native-composition-followup/m3` (general nested workflow invocation).
- **Minimum plan amendment:** This is deferred to `native-composition-followup/m3` and is a **missing contract**, not deferred detail. The plan must specify: (a) dynamic `foreach` compilation into `ParallelInstruction` with per-iteration `run_path`, (b) per-iteration checkpoint in child artifact roots, and (c) reducer receipt aggregation into parent boundary. Without this, the current plan for `boundary-turn-end-to-end/m6` (execute child batch turns) is underspecified.

### Gap 8: Cancellation is not a first-class RA or WBC state (MEDIUM)
- **Severity:** MEDIUM
- **Confidence:** MEDIUM
- **Consequence:** Cancellation is handled at the supervisor/envelope level (`RunEnvelope.cancellation`, `CancellationRequested`) but the RA resolver has no CANCELLED state and WBC has no cancellation outcome. A cancelled run is classified as UNKNOWN or BROKEN_STATE_MACHINE, not as intentionally terminated.
- **Evidence:** `model.py:18-35` — `CanonicalState` enum has 9 states, none for CANCELLED. `boundary_evidence.py:45-59` — `BoundaryOutcome` has 11 states, none for CANCELLED (closest is `VOIDED` or `SUPERSEDED`). `runtime.py:69-74` — cancellation is handled at the runtime level.
- **Minimum plan amendment:** Add `CANCELLED` to `CanonicalState` enum with a classifier that fires when `envelope.cancellation == True` and the worker is not live. Add `CANCELLED` to `BoundaryOutcome`. This is a straightforward amendment to the existing enums.

### Gap 9: No WBC receipt idempotency proof (MEDIUM)
- **Severity:** MEDIUM
- **Confidence:** MEDIUM
- **Consequence:** `BoundaryReceipt` has no `idempotency_key` field. If a receipt is emitted twice (replay, duplicate phase execution), there is no way to detect the duplicate from the WBC evidence layer alone.
- **Evidence:** `boundary_evidence.py:158-254` — `BoundaryReceipt` has `invocation_id`, `artifact_refs`, `state_observation` but no `idempotency_key`. `effect_ledger.py:30-36` — `EffectRecord` has `descriptor` with `idempotency_key`. These are disconnected.
- **Minimum plan amendment:** Add `idempotency_key: str | None` to `BoundaryReceipt`. On receipt emission, derive the key from `(boundary_id, invocation_id, contract_version)`. Validate uniqueness before writing. This bridges the WBC receipt layer with the effect ledger deduplication.

### Gap 10: No custody epoch in RA or WBC vocabularies (LOW)
- **Severity:** LOW
- **Confidence:** MEDIUM
- **Consequence:** When a custody lease is reassigned (e.g., from coordinator A to coordinator B), there is no durable epoch marker in RA or WBC evidence. History queries cannot distinguish which coordinator owned which phase.
- **Evidence:** `capacity_lease.py:86-105` — `CapacityLease` has `tenant` + `fencing_token` but no epoch counter. `RunEnvelope` has `lease_id` + `fencing_token` but no epoch. `classifiers.py` doesn't read any custody field.
- **Minimum plan amendment:** Add `custody_epoch: int` to `RunEnvelope`, incremented on each `CapacityLease.acquire()`. Include in RA evidence so the resolver can detect epoch transitions. This is a implementation detail appropriately deferred to the custody-wiring sprint, but the data field must be declared now.

**Summary position:** The four coordinates (authored topology, RA, WBC, Custody) are individually sound but operate in separate identity spaces. The critical path to integration is: (1) add identity bridging between authored nodes and WBC `boundary_id`, (2) wire `EffectLedger` into the native runtime with checkpoints after every effect-bearing phase, (3) make the RA resolver custody-aware, and (4) snapshot the compiled program hash in the resume cursor. Without these four bridges, cross-coordinate scenarios (crash-after-effect, cross-host resume with custody, dual-coordinator execution) produce silently incorrect behavior with no detectable evidence until a downstream consumer observes the duplicate or inconsistency.
