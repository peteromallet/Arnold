## Swarm Audit: S1c Runtime Substrate Proof

### 1. Verdict: **Partly exists**

The native runtime substrate (`arnold/pipeline/native/`) has comprehensive implementations of all four sub-components. However, the bridge from Megaplan's DSL workflow to this runtime has not been proven, and the required S1b-1 exit-gate tests don't exist. The old DSL-level executor (graph-based) does not resolve `items_ref` dynamically.

### 3. What Can Be Reused or Generalized

| Existing | Generalizable to |
|---|---|
| `_resolve_parallel_map_items()` (`runtime.py:421`) | Already generic — resolves from `state`/`parameter_values`. Ready to use for any pipeline. |
| `NativeParallelMapStage.run()` (`graph_projection.py:231-300`) | Wraps `run_native_pipeline` for each mapper child. Can be extracted as a standalone bridge adapter. |
| Checkpoint cursor format (`checkpoint.py`) | Already generic. `classify_resume_cursor` routes to native vs graph executor. |
| `parallel_map` decorator (`decorators.py:456`) | Already framework-agnostic. Marks callables with `__parallel_map_items__`, etc. |
| `project_graph` → `Pipeline` shell (`graph_projection.py`) | Bridges native programs into the DSL `Pipeline` shape with `native_program` attached. Can drive the Megaplan compatibility path. |
| `_compatibility.py:173-207` — `_native_program_from_dsl` | Already projects DSL steps into `NativeProgram`. The route from `.pypeline` → `NativeProgram` → native runtime exists structurally. |

**Key refactor path**: The native runtime already handles all substrate concerns. The gap is that Megaplan's `workflow.pypeline` is still routed through the old graph executor (or CLI `COMMAND_HANDLERS` via `_compatibility.py:235-267`). The substrate proof should demonstrate that lowering the `.pypeline` through `_native_program_from_dsl` and executing via `run_native_pipeline` satisfies all four sub-components without `handler_ref`.

### 4. What Still Must Be Built

1. **Exit-gate tests don't exist.** None of these are present:
   - `tests/arnold_pipelines/megaplan/test_native_runtime_dynamic_fanout.py`
   - `tests/arnold_pipelines/megaplan/test_native_runtime_suspension_reentry.py`
   - `tests/arnold_pipelines/megaplan/test_native_runtime_loop_exits.py`
   - `tests/arnold_pipelines/megaplan/test_runtime_items_ref_resolution.py`
   - `tests/arnold_pipelines/megaplan/test_manifest_backend_source_dispatch.py`

2. **DSL-level dynamic fanout runtime proof.** The old graph executor's `FanoutPolicy` only has `width: int | None` (`arnold/manifest/manifests.py:96-101`), not `items_ref`. The master plan's Q1 audit confirmed this (`master-plan.md:204`): "the neutral router only fans out from static `width`; `items_ref` is not resolved at runtime." The proof must show that a `Step(kind="parallel_map")` with `mode="dynamic"` actually resolves `items_ref` and spawns children — either through the native runtime or a patched DSL executor.

3. **Source-derived manifest dispatch without `handler_ref`.** `_compatibility.py:235-267` currently dispatches through `COMMAND_HANDLERS.get(phase_name)` (CLI handlers). The proof must demonstrate one builder edge (e.g., a single phase from `workflow.pypeline`) executing through lowered source constructs without `handler_ref` as semantic authority.

4. **Megaplan-specific suspension/reentry fixtures.** Native runtime supports suspension generically, but no Megaplan workflow-specific fixture proves a `workflow.pypeline` phase can suspend, checkpoint, and resume correctly.

---

### 5. Recommended Adjustment to Sprint Plan

**Risk**: The native runtime substrate is feature-complete internally, but the bridge to Megaplan's `.pypeline` source has not been wired or tested. The gap is integration, not substrate capability.

**Recommendations:**

1. **Consolidate S1b-1 into a bridge-proving sprint rather than a substrate-building sprint.** The native runtime already provides `parallel_map`, suspension, loop exits, and source-derived dispatch. Build the integration tests that prove the lowered DSL → native runtime path works for these constructs.

2. **Add one explicit integration fixture**: lower a minimal `workflow.pypeline` fragment containing `parallel_map(items=..., step=...)` through `source_compiler.lower_workflow_source()` → project through `_compatibility._native_program_from_dsl()` → execute via `run_native_pipeline()` → verify children spawn and reducer runs. This single test covers items_ref resolution, suspension, and source-derived dispatch simultaneously.

3. **`test_manifest_backend_source_dispatch.py` should verify that `handler_ref` is not consulted during native runtime execution.** The `_compatibility._run_megaplan_native_phase` function at `_compatibility.py:243` already does `del handler_ref` (ignores it), but the dispatch still goes through `COMMAND_HANDLERS`. The proof should instead show dispatch via `NativeInstruction.func` from lowered source.

4. **Loop exit tests can be scoped down.** The native runtime already supports loop exits via `LoopGuard`/`exit_pc` in composition. Unless S2-S5 require typed exit payloads, existing support is probably sufficient.

5. **Unverified prior claim**: The master plan references `runtime/manifest_backend.py:227-322` as a current carrier, but this file does not exist in the repo. This appears to be either a planned target or a removed file. The sprint should verify the reference or replace it with the actual dispatch path (CLI `COMMAND_HANDLERS` + `_compatibility.py`).
