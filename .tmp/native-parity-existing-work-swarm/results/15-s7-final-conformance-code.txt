### 3. What Can Be Reused or Generalized

1. **`generate_native_representation_evidence.py:1607-1712`** — `generate_evidence_bundle()` already produces `scenario_hashes`, `installed_package_fingerprints`, `handler_purity_checks`, `compatibility_quarantine_checks`, `dead_delete_mutation_checks`. This is the evidence engine S7's `generate_megaplan_native_semantic_conformance.py` should consume. It produces ~90% of the data the generated conformance report needs.

2. **`source_compiler.py:722-810`** — `_row_evidence_diagnostics()` is the strict checker engine. S7's `check_megaplan_native_semantic_parity.py` needs to invoke this with `evidence=()` (strict mode) and produce JSON output with row IDs, spans, source hashes, and carrier classification. The engine exists; the CLI wrapper and JSON output format do not.

3. **`source_compiler.py:1682-1868`** — `_implemented_front_half_rows()` and `_implemented_s5_boundary_rows()` define the current row registry. These should be externalized into `megaplan_semantic_rows.yaml` (S1a work), then consumed by S7 reconciliation.

4. **`validate_native_representation_conformance.py`** — the `validate_conformance_ledger()` function and its evidence-record parsing can be adapted into the S7 generated report validator.

5. **Existing test fixtures** in `test_final_conformance_evidence.py` — `_write_evidence_bundle_fixture()`, `_checker_evidence_record()`, `_write_traceability_fixture()` helpers are reusable for S7 integration tests.

### 5. Recommended Adjustment to Sprint Plan

**Severity: The S7 spec assumes S1a through S6 have all completed, and S7 is "assembly + final gates." In reality, S7's eight scripts are net-new builds with zero scaffolding.** Recommended adjustments:

1. **Split S7 into S7a (scripts + infrastructure) and S7b (final execution pass).** Bring S7a forward to run in parallel with S5-S6 so the tooling is ready when extraction finishes.

2. **Promote `generate_native_representation_evidence.py` to the canonical evidence engine** rather than building a parallel one. Its `generate_evidence_bundle()` already covers scenario hashes, installed fingerprints, handler purity, compatibility quarantine, and dead-delete checks. Add a `--strict-checker-json` input flag to consume the output of the yet-to-be-built `check_megaplan_native_semantic_parity.py`.

3. **Descope the full `scan_megaplan_semantic_carriers.py` from S7 to S1a** — the master plan already specifies S1a does the first package-wide scan (`:413-426`). S7 should re-run the same scan with a frozen exclusion list, not build a new scanner.

4. **Add an explicit S7 prerequisite: `megaplan_semantic_rows.yaml` must be externalized from `source_compiler.py:1682-1868`.** The row registry currently lives in Python code. The reconciliation script needs it as a data file.

5. **The five existing test files are thin guards, not end-to-end conformance proofs.** Each needs expansion: `test_final_conformance_scenarios.py` (3 tests) should grow to cover the full split-outcome inventory and cross-reference with row coverage; `test_installed_package_composition_smoke.py` should add `check_megaplan_native_semantic_parity.py --mode installed-package` invocation once that script exists.

**Prior report claims (unverified):** The master plan root-cause analysis (:167-170) cites a "false conformance report" (`megaplan-native-representation-conformance-report.md`) claiming all 31 rows implemented. The current `megaplan-native-representation-conformance.yaml` has ~27 rows with `status: implemented`. This ledger is the old path-existence-based system, not the S7 strict-checker-generated conformance — confirming the master plan's diagnosis that the old report is a false pass.
