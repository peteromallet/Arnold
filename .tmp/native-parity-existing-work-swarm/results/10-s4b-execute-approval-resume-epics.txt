### 5. Recommended Adjustment to Sprint Plan

**S4 should be split into two sprints: S4a (Approval + Resume policy extraction) and S4b (Execute DAG + batch topology).** The current S4 scope in the master plan (line 693–728) conflates approval/resume (which has mature typed policy surfaces ready for extraction) with execute DAG/batching (which is deeply entangled with handler/auto code and has no typed pure-function layer yet).

**S4a** (Approval + Resume): Extract the approval gate and resume cursor into source-visible lowered constructs first, since the typed policy layer (`evaluate_destructive_approval`, `evaluate_no_review_terminal`, `evaluate_blocker_recovery_policy`, `_resolve_resume_cursor`) already exists and is directly liftable. Add the headless control-injection API as a prerequisite.

**S4b** (Execute DAG + batch): Build the batch topology extraction after S4a's policy surfaces are proven, since batch execution depends on approval having cleared and resume being source-owned. This is the harder half and should not block S4a closeout.
