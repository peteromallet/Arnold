## 3. What Can Be Reused or Generalized

- **`_build_gate_carry`** and **`_write_gate_carry`**: Add `north_star_actions` as a new top-level key. This is a field addition to an existing dict builder. Revise already reads `gate_carry.json` (via `_gate_summary_or_skipped` in `prompts/_shared.py:22` and `prompts/execute.py:658`), so the read path exists — only the prompt rendering of the new field is new.
- **`_SEVERITY_HINT_CANONICAL` / `_normalize_critique_flag_severity`** pattern: A `_normalize_north_star_action_severity` function can follow the same post-worker normalization pattern, overriding dangerous categories to `blocking` before routing.
- **`_is_cap_blocking_flag`** pattern: Extend `_CRITICAL_CATEGORIES` or add a parallel `_is_north_star_blocking` that checks action categories (route_authority, baseline_rewrite, etc.) and forces blocking severity.
- **`_normalize_prep_open_question`** pattern: Handler-enforced severity override already proven in the codebase — North Star severity normalization is not a new concept.
- **`MilestoneSpec` / `ChainSpec` dataclasses**: Adding `north_star_critical: bool = False` is a field addition. Robustness rejection logic during `from_dict` already validates other field combinations (e.g., `chain/spec.py:884-888` for `escalate_action`).

## 4. What Still Must Be Built

1. **Runner pinning scripts** (`pin_megaplan_runner.py`, `check_megaplan_runner_pin.py`): New from scratch. Must capture commit SHA, package fingerprint, profile, robustness, auto-drive corpus version, and produce/validate a JSON pin record.
2. **`north_star_actions` schema + gate/carry field**: New field in `_build_gate_carry`, gate prompt rendering, and gate scratch→canonical promotion.
3. **`north_star_actions_addressed` in revise**: New field in `revise_meta_fields`, prompt rendering, and post-worker structural validation (prose-only claims must fail).
4. **Pre-worker halt guard**: New control-flow logic in `handle_revise` before the worker is invoked — halt on `add_human_halt`, unmappable blocking actions, baseline rewrites, route-authoritative exemptions, target narrowing, live-plan topology decisions.
5. **Post-worker revise validation**: New validation after worker returns — verify `plan_refs` are concrete, action-specific structural markers exist.
6. **`north_star_critical` schema field**: New field on `ChainSpec` and `MilestoneSpec`, with robustness rejection (`bare`/`light` + `north_star_critical: true` → error).
7. **Severity normalization for dangerous categories**: New handler-side normalization that overrides agent-claimed severity to `blocking` for route authority, baselines, row/carrier exemptions, target narrowing, generated conformance authority, live-plan topology/resume risk.
8. **Clean-context auditor**: New subagent/invocation pattern for explanation-style North Star questions — launches a separate principal from a different model family, predicts behavior from source alone, verifies against run evidence.
9. **Finalize/review enforcement**: New logic in finalize to lower North Star obligations into executable tasks/checks; new review logic to block closeout for unresolved `reject_closeout` actions.
10. **Six test files + canary audit infrastructure**: All new.
11. **North Star question parsing** from `NORTHSTAR.md` and sprint briefs: New parsing logic to extract `## Sprint Review / North Star Sense Check` questions.

## 5. Recommended Adjustment to the Sprint Plan

**Risk: LOW (design-complete, code-absent, adjacent infrastructure is healthy).** S0 is a pure plumbing sprint with no semantic extraction — it adds structured action fields to existing feedback loops. The adjacent mechanisms are robust and well-tested.

**Recommendations:**

1. **No extraction risk**: S0 modifies only the Megaplan runner tooling (gate/revise/finalize/review handlers, chain spec, prompts). No `.pypeline` source changes. Rollback is safe.

2. **Prioritize the gate→revise carrier path first** (items 2, 3, 5 above). The `gate_carry.json` → revise pipeline already works. Adding `north_star_actions` as a field and rendering it in the revise prompt is the smallest blast-radius change. The pre-worker halt guard (item 4) should land in the same change to avoid a window where blocking actions reach the worker without interception.

3. **Severity normalization should live in the gate handler**, not only in prompts. The gate handler already has `_is_cap_blocking_flag` (`gate.py:379`) — extend this pattern with a `_normalize_north_star_severity` that runs before routing. The master plan confirms this at lines 346-348: "This override belongs in the gate/review handler, not only in prompts."

4. **Defer the clean-context auditor to a follow-on sprint if necessary**. The design doc (`megaplan-north-star-sense-checks-revise-design.md:469-471`) explicitly says: "Review backstops, clean-context canaries, and skill-template polish can be follow-on work." The canary audit is an S0 exit gate but the canary *infrastructure* could be a thin wrapper around the existing Hermes subagent launcher.

5. **The `north_star_critical` schema field should validate at `ChainSpec.from_dict` time**, where `driver` keys are already parsed (`chain/spec.py:870-932`). Reject `north_star_critical: true` + `robustness` ∈ {`bare`, `light`} immediately — do not silently upgrade robustness. This is a 5-line addition to `from_dict`.

6. **No prior report claims S0 completion.** The design docs are explicit that this is to-be-built ("What Needs To Be Added", North Star design doc lines 369-416; S0 scope in master plan lines 344-405). There are no unverified prior claims to challenge.
