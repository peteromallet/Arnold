### 5. Recommended Adjustment to Sprint Plan

**Risk: S7 is gated on 11 scripts + 6 data artifacts that don't exist yet, plus S1a-S6 completion.** The existing `generate_native_representation_evidence.py` provides ~40% of the evidence-collection surface, but none of the authoritative gate scripts. Recommended adjustments:

1. **Split S7 into S7a (infrastructure) and S7b (execution).** S7a builds the scripts and data files S1a already depends on (carrier scan, row registry, baseline freeze). S7b runs the final gates.

2. **Generalize, don't rewrite.** `generate_native_representation_evidence.py:1607-1712` already produces the evidence bundle that S7's generated report consumes. Refactor rather than build parallel infrastructure. The bundle builder's `_build_split_outcome_hashes`, `_build_installed_package_fingerprints`, `_build_handler_purity_checks`, `_build_compatibility_quarantine_checks`, and `_build_dead_delete_mutation_checks` all produce structured output already.

3. **The installed-package strict checker path is the highest-risk gap.** The smoke test loads source via `importlib.resources` (`test_installed_package_composition_smoke.py:466`), but the strict checker (`check_workflow_source`) does not. This must be resolved in S1a before S7 can close.

4. **Consider collapsing some S7 scripts.** The carrier scan → classification → reconciliation → exemption pipeline could be a single `scripts/reconcile_megaplan_semantic_carriers.py` with subcommands rather than four separate scripts. Similarly, baseline freeze + amendment validation could merge.

5. **De-risk the scenario-row matrix.** `scenarios.yaml` already declares `rows` per scenario. The matrix script (`generate_megaplan_scenario_row_matrix.py`) can consume existing YAML + checker JSON without new data files.
