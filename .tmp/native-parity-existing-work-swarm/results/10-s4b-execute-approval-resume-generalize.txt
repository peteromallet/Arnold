### 3. What Can Be Reused or Generalized

- **`execute/policy.py`** is the single most reusable asset. Every typed outcome (approval deny/approve, blocked retry, no-review terminal, resume partition) is already a pure function — it can be directly wired into a native workflow without handler mediation.
- **`EXECUTE_BRANCH_SURFACE`** (policy.py:860-1042) declares the complete execute routing topology. It can feed directly into the `.pypeline` route bindings.
- **`evaluate_blocker_recovery_policy`** (policy.py:528-623) is the adjacent mechanism most directly generalizable — it wraps the existing `blocker_recovery.evaluate_blocker_recovery` into a typed `BlockedRetryDecision`, demonstrating the pattern for extracting other handler-owned decisions.
- **The resume cursor schema** (`batch.py:1622-1627`, `handlers/execute.py:107-109`) is consistent and could be generalized into a typed `ResumeCursor` dataclass (currently ad-hoc dicts).
- **Boundary receipt emission** (`handlers/execute.py:223-301`) is evidence-only and can be lifted to the workflow layer without changing semantics.

### 4. What Still Must Be Built

1. **Exit-gate integration test** — `tests/arnold_pipelines/megaplan/test_execute_native_dag_approval_resume.py` does not exist. This is the S4 closeout gate per master plan line 702.
2. **`blocked_retry_byte_stability` test** — referenced in the folder audit (`audit.md:426`) but file not found in current tree.
3. **Old carrier extraction** — `components.py:1641-1654` (execute:resume route), `:1694-1709` (fanout contract, blocked retry), `:1781-1822` (model routing) still carry route authority. These must be deleted/quarantined per master plan lines 718-719.
4. **`handler_ref` removal** — `workflow.pypeline:220` still declares `handler_ref: "arnold_pipelines.megaplan.handlers:handle_execute"`. Native lowering must replace this with a lowered subworkflow.
5. **Resume cursor typed dataclass** — Currently ad-hoc dicts (3 sites: `batch.py:1622`, `handlers/execute.py:108`, `components.py:1465`). Should be a single `ResumeCursor` type shared across policy and runtime.
6. **Strict checker rejection rules** for handler-owned execute route decisions (master plan line 705).

---

### 5. Recommended Sprint Plan Adjustment

- **Keep S4b as a single sprint** but split into two sub-deliverables:
  - **S4b-1 (policy hardening):** Add the typed `ResumeCursor` dataclass, write `test_execute_native_dag_approval_resume.py` covering all 6 split outcomes (master plan line 706), add strict-checker rejection for handler-owned execute routes. This is low-risk — all policy functions are pure, tested in isolation.
  - **S4b-2 (carrier extraction):** Extract `components.py` execute fanout/route surfaces, remove `handler_ref` from `workflow.pypeline:220`, lower execute through the native `.pypeline` path. This is higher-risk because it changes the dispatch path.
- **Risk:** The `handler_ref` at `workflow.pypeline:220` means execute currently routes through `handle_execute`, which does substantial work beyond pure policy translation (preflight checks, profile expansion, tier model resolution, workdir warnings). Lowering must replicate these in native workflow form.
- **Adjacent mechanism to watch:** `evaluate_blocker_recovery_policy` (policy.py:528) already wraps `blocker_recovery.evaluate_blocker_recovery` — this is the template for extracting other handler-owned decisions. But `blocker_recovery` itself still lives outside the policy module and must be audited for handler coupling before it can be claimed as native authority.
