## 4. What still must be built

1. **Retained-handler typed interfaces**: `Protocol` classes or `TypedDict` contracts with `allowed_side_effects` declarations per the M2 brief spec. Currently zero such declarations exist.

2. **Full lowered-topology builder for at least one edge**: `_canonical_steps` (`:643-672`) must derive step `kind`, `inputs`, `outputs`, `policy`, and `metadata` from lowered source WITHOUT falling through to `PIPELINE_STEP_COMPONENTS_BY_ID`. The simplest target is prep or plan (single-input, single-output, no loop).

3. **Edge-specific dead-delete test**: A test that mocks/removes the prep or plan component's `route_bindings` from `PIPELINE_STEP_COMPONENTS_BY_ID` and proves `build_pipeline()` produces an identical `Pipeline` (same steps, same routes, same topology hash).

4. **Handler purity scanner with side-effect declarations**: The M2 brief requires "transitive handler-purity scanner support: retained handlers declare allowed side effects, and the scanner checks callees for report-owned routing." The existing evidence generator (`scripts/generate_native_representation_evidence.py`) has handler-purity checks but no side-effect declaration mechanism.

5. **Prove canonical source can branch on typed outcomes**: Currently the `.pypeline` source branches on raw string comparisons like `gate_route_signal == "proceed"` (`workflow.pypeline`). The outcomes enums exist but are not yet the authoritative branch mechanism in source.

## 5. Recommended adjustment to the sprint plan

The conformance report at `docs/arnold/megaplan-native-representation-conformance-report.md:48` claims row 23 `typed-loop-outcomes` as "implemented" with `canonical_source` evidence, but the master plan at `megaplan-native-semantic-parity-master-plan.md:167` explicitly calls this report a "false conformance report." **Do not treat any row as pre-completed.** 

For S1d, I recommend:

- **Keep**: Typed outcome enums — they are done and tested.
- **Add explicit scope**: Select prep→plan as the one edge, make `_canonical_steps` derive that step entirely from lowered source (remove `PIPELINE_STEP_COMPONENTS_BY_ID` dependency for that edge), and add the dead-delete test proving component binding removal doesn't change the trace.
- **Defer**: Full retained-handler Protocol/interface definitions and allowed-side-effect declarations — these can be done incrementally as each handler's phase is extracted in S2-S6 rather than all upfront.
- **Add before closeout**: The edge-specific dead-delete test (disabling old component route bindings for prep→plan) — this is the key anti-false-pass guard that the current codebase completely lacks.
