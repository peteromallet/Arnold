## 4. What still must be built

1. **S1b-2 exit gate tests do not exist.** No files match `test_workflows_planning_lowered_topology.py` or `test_installed_package_composition_smoke.py` in the test tree. These are the master plan's explicit exit gates (`master-plan.md:590`).

2. **Single-edge dead-delete behavior test.** The master plan requires: "delete/mutate old component `route_bindings` for that edge and prove behavior/output unchanged" (`master-plan.md:594-595`). The existing execute test (`test_workflows_components.py:141`) only asserts empty bindings — it doesn't mutate them and re-run behavior scenarios against frozen baselines.

3. **build_pipeline still hybrid, not source-owned for the selected edge.** `_route_id_for_lowered_route()` still consults component bindings (`planning.py:255-257`), `_metadata_for_step()` still reads `handler_ref` from components (`planning.py:587-589`), and `_policy_for_step()` gets its base policy from components (`planning.py:557-558`). For S1b-2 to close, one edge must route purely from lowered topology with component metadata inert or deleted.

4. **Installed-package parity smoke.** No test or script validates that `workflow.pypeline` loaded via `importlib.resources` produces identical checker output to checkout mode. The master plan requires this at S1b-2 (`master-plan.md:584`).

5. **No frozen S1a baselines exist to diff against.** The S1a pre-extraction baseline freeze script (`scripts/capture_megaplan_split_outcome_baselines.py`) has not been run (no `artifacts/native-semantic-parity/baselines/pre-extraction/` directory evidence), so S1b-2 parity checks cannot diff against frozen legacy behavior.

## 5. Recommended adjustment to the sprint plan

**S1b-2 (Typed Outcomes + Builder Slice) is partly built.** The typed outcomes infrastructure (`outcomes.py`, 252 lines, 15+ StrEnum classes) is substantially complete and exceeds the "one edge" minimum. The builder infrastructure (`_lowered_workflow()`, topology helpers) is wired but still hybrid.

**Recommendation: Narrow S1b-2 to the specific delta:**

- **Keep:** `outcomes.py` as-is — it already covers all workflow domains and has parity guardrails.
- **Add only:** (a) one concrete edge where `build_pipeline()` route resolution for that edge is proven to work with component `route_bindings` deleted/mutated, with a dead-delete behavior test; (b) the `test_workflows_planning_lowered_topology.py` test proving lowered topology is consumable; (c) the installed-package smoke test; (d) S1a baseline capture before this sprint starts, since the master plan requires it (`master-plan.md:596`).
- **Do not expand:** The existing `outcomes.py` coverage means the "typed outcomes" workload for S1b-2 is essentially done. Do not add new outcome domains — use the sprint to prove one edge's source-ownership and installed-package parity, then move to S2.

**Risk:** The hybrid builder could create a false-pass if the selected edge appears to route from lowered topology but a component fallback (`planning.py:255-257`) silently saves it. The dead-delete test must actually delete the component binding, not just assert it's empty.

**Unverified prior claim:** The evidence YAML marks `typed-loop-outcomes` as having a proof artifact (`megaplan-native-representation-evidence.yaml:395-408`) but this is a carrier reference to the full `.pypeline` file, not behavior evidence that one specific edge routes without component bindings. Treat as descriptive metadata, not closure proof.
