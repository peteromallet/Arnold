### 3. What Can Be Reused or Generalized

- **Handler code is a complete semantic oracle.** `handlers/gate.py` implements every S2b behavior correctly and can serve as the reference for parity tests without modification.
- **Policy catalogue** (`policy_catalogue.md:7-17`) precisely documents the semantics that native extraction must preserve.
- **Native interfaces** already define stable IDs (`megaplan.native.gate.v1`, `megaplan.native.revise.v1`, etc.) and typed input/output contracts for wiring.
- **Gate route signal vocabulary** (`_build_gate_route_signal()` at `:523-712`) maps all recommendations (PROCEED/ITERATE/TIEBREAKER/ESCALATE/ABORT/SUSPEND) to concrete `route_signal` strings — these become native branch labels.
- **Flag/severity/debt infrastructure** (`flags.py`, `planning/control_binding.py:674-689`) is independent of handler dispatch and can be retained as phase bodies.
- **`front_half.pypeline:29-31`** already declares the `critique-gate-revise` handoff contract, providing the anchor for native extension.
- **Preflight checks** (`gate_checks.py`) are pure functions with no handler coupling and can be called directly from native source.

1. **Native gate/revise `.pypeline` source.** The entire critique→gate→revise loop must be expressed as native source constructs (branches for PROCEED/ITERATE/TIEBREAKER/ESCALATE/ABORT, reprompt path, downgrade path, loop caps, no-progress termination). Currently zero lines exist.

2. **Gate route signal → native branch lowering.** `_build_gate_route_signal()` returns string route signals consumed by the DSL router; these must become native branch constructs in source.

3. **Reprompt and auto-downgrade as native source paths.** Currently at `handlers/gate.py:993-1094` as imperative logic. Must be visible control flow.

4. **Severity-gated cap termination as native branches.** `_critique_terminate_branch()` at `:466-521` chooses escalate vs force-proceed based on flag categories. Must become a source-level branch.

5. **Iteration caps and no-progress tracking as declared policy.** Currently scattered across `_effective_critique_cap()` (`:345-357`), `_prior_iterate_rounds()` (`:358-371`), `_critique_no_progress_streak()` (`:414-463`), and `components.py:1287-1308`. Must attach to native loop constructs as declared policy.

6. **Debt recording as a phase body or declared policy effect.** `_record_gate_debt_entries()` at `:77-133` must be callable from native source or expressed as a policy side-effect.

7. **Tests.** No gate/revise-specific test files found under `tests/arnold_pipelines/megaplan/`. The master plan requires `test_front_half_native_loop.py` including split-outcome scenarios for reprompt/downgrade, critical cap exhaustion, cosmetic cap exhaustion, force-proceed, and abort (`master-plan.md:628-632`).

### 5. Recommended Adjustment to Sprint Plan

- **S2 should remain one sprint** (not split into S2a/S2b). The master plan already treats gate/revise as one extraction unit because gate route groups and revise reentries are coupled (`components.py:1154-1158`, `:1276-1279` per `master-plan.md:624`).

- **Add a pre-extraction baseline freeze step.** Before extracting gate/revise, capture golden baselines from the handler path for all gate recommendations (PROCEED/ITERATE/TIEBREAKER/ESCALATE) and cap-exhaustion outcomes. The master plan gates this at `:630`.

- **Prioritize split-outcome scenarios early in the sprint.** The hardest native constructs to get right are the reprompt/downgrade path and severity-gated cap termination. Build these scenarios first, before the happy-path PROCEED.

- **Retain flag/debt infrastructure as phase bodies.** `flags.py` and debt functions in `planning/control_binding.py` are pure data operations with no route authority — they don't need native extraction. Focus extraction on the control-flow decisions, not the data bookkeeping.

- **Clear `components.py:1154-1336` gate/revise policy surfaces after extraction.** The sprint closeout must fence or delete these route groups, severity policies, and revise_reentries as route authority (`master-plan.md:642-644`).
