## 1. Verdict: **Partly exists**

The native pipeline substrate (`arnold/pipeline/native/`) has substantial parallel_map, suspension/reentry, and loop exit infrastructure. But the component is unproven at the Megaplan DSL/manifest layer, and the source-derived dispatch without `handler_ref` does not exist at all. The plan itself (master plan §S1b-1, lines 532–576) treats these as unproven prerequisites.

## 5. Recommended adjustment to the sprint plan

**The S1b-1 milestone does not appear in `chain.yaml`** — it still uses the pre-split `m1-checker-outcomes-builder-slice` milestone (`chain.yaml:32`). The master plan resolved the S1 split (lines 947–950) into S0, S1a, S1b-1, S1b-2, but the initiative's chain file was never updated.

**Recommendation**: Add S1b-1 as a dedicated milestone between S1a (`checker authority`) and S1b-2 (`typed outcomes/builder slice`). The milestone should:

1. **Reuse** the proven native `parallel_map` runtime (compiler/IR/runtime from `arnold/pipeline/native/`) rather than rebuilding substrate
2. **Focus effort on the three real gaps**: source-derived manifest dispatch, Megaplan-integration runtime proof tests (the five missing test files), and end-to-end dynamic fanout through the manifest path
3. **Lower ambition on suspension/reentry and loop exits**: these have working substrate (`runtime.py:1209–1290`, `:1675`, M3 donor hooks); the S1b-1 work is proving them end-to-end in the Megaplan context, not building new mechanisms
4. **Add a dead-delete prerequisite**: the manifest backend's `HANDLER_NODE_IDS` dispatch (`manifest_backend.py:72–84`) must be replaced or proven inert for the S1b-1 edge before S2 extraction depends on dynamic fanout
