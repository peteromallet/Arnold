## 5. Recommended Adjustment to the Sprint Plan

**S1b should be treated as a greenfield build sprint**, not a wiring sprint. The adjacent code provides building blocks (semantic equivalence comparison, cursor validation, scenario YAML schema, evidence generator patterns, installed-package smoke patterns), but none of the six sub-components exist as a working substrate.

**Specific recommendations:**

- **Replay harness**: Build on `semantic_replay_journal()` from `arnold/runtime/semantic_replay.py` but replace event-journal input with canned worker payload injection. The `semantic_equivalent()` comparator is directly reusable.

- **Split-outcome inventory**: The YAML file exists and is well-structured. Add a completeness validation step (the master plan's `validate_megaplan_split_outcome_scenarios.py` script doesn't exist yet either) rather than rebuilding the inventory.

- **Installed-package smoke**: Extend `test_installed_package_composition_smoke.py` or build a parallel `test_installed_package_strict_source_loading.py` that routes source through the strict checker, not just through `build_pipeline()`/`compile_pipeline()`.

- **Canonicalizer**: Defer as designed — the master plan triggers it only when artifact hashes are used as parity proof (line 62: "Canonicalized artifact hashes are added only when artifact content is used as parity proof"). Do not build it in S1b unless artifact-hash baselines are committed to.

- **Headless control injection**: This is a new API surface with no adjacent code. It needs fresh design — the master plan scopes it to "destructive approval denial, destructive approval approval, tiebreaker proceed/iterate/escalate" only (line 445-448). Build the minimal surface.
