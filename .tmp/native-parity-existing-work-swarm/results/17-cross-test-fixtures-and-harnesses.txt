### Gaps

1. **Replay harness** — `replay_manifest()` (`tests/arnold/execution/fixtures.py:166`) declares idempotency policy but no test replays a full execution and verifies deterministic output against a golden trace directory. The infrastructure (`compare_native_golden_dir`, idempotent manifest) is present but unassembled.

2. **Canary suite** — No dedicated lightweight (<10s), always-run canary test file. `_smoke_trace_test.py` exists at project root but is not integrated into the test runner as a canary marker.

3. **Auto-drive characterization** — `test_auto_native_dispatch.py` covers dispatch plumbing but no end-to-end characterization test that drives a plan through all phases (prep→plan→critique→gate→revise→finalize→execute→review) and asserts expected state transitions per policy.

4. **Transition policy — neutral conformance** — `TransitionPolicy` lives in `arnold_pipelines/megaplan/orchestration/`. No neutral-package conformance test validates the policy contract shape independently of the Megaplan implementation.

5. **Deleted-surface resurrection guard** — `test_deleted_surfaces.py` verifies *current* physical absence, but no pre-commit/CI gate prevents new import references from being added back to `DELETED_IMPORT_MODULES`.

6. **Headless-mode integration** — Headless resume is tested indirectly (`test_control_resume_runner.py`, `test_auto_recover_blocked.py`), but no explicit test simulates a full suspend→auto-resume (canned human_input)→completion cycle without any interactive prompt.

7. **Installed package CLI surface coverage** — Wheel smoke (`test_m5_wheel_smoke.py:91`) only tests `workflow check/manifest/dry-run`. Remaining CLI subcommands (status, resume, operators, etc.) are untested from an installed wheel.

8. **Checker fixtures — failure-mode characterization** — Existing fixtures are structural (toy pipeline, manifest builders). No fixtures pre-populate specific failure modes (gate contradiction, worker timeout, evidence staleness) to enable deterministic checker-behavior characterization.

9. **Approval→transition-policy integration** — `TransitionWriter` denial logic and `evaluate_destructive_approval` are tested in isolation. No integration test validates that a policy denial correctly cascades through the approval→resume→routing pipeline.

---

### Plan Adjustments

1. **Assemble replay harness** — Combine `replay_manifest()` + deterministic executor + `compare_native_golden_dir()` to verify full replay produces bit-identical trace directories.

2. **Create canary suite** — Extract `_smoke_trace_test.py` into `tests/canary/` with 5–8 tests (native compile+run, manifest validation, import boundaries, golden trace comparison), all under 10s, marked `@pytest.mark.canary`.

3. **Extend installed-wheel CLI coverage** — Add `test_m5_wheel_smoke.py` cases for `arnold workflow status`, `arnold workflow resume --help`, `arnold operators list`, verifying all shipped entrypoints.

4. **Build auto-drive characterization** — Use native golden scenarios D1–D15 as inputs, drive a plan through all phases programmatically, assert resulting `state.json` and trace directories match golden records.

5. **Add neutral transition-policy conformance test** — Validate `TransitionPolicyDecision` shape contract in `tests/arnold/conformance/` without importing `arnold_pipelines.megaplan`.

6. **Add resurrection guard (CI)** — Pre-commit or CI gate using `scripts/check_workflow_pipeline_inventory.py` pattern to scan for new references to `DELETED_IMPORT_MODULES`.

7. **Build headless integration fixture** — Create a test that suspends a native pipeline (via `HumanSuspension`), auto-resumes with canned `{"approved": true}`, and asserts completion without interactive I/O.

8. **Add failure-mode checker fixtures** — Extend `tests/arnold/execution/fixtures.py` with pre-built manifests encoding specific failure modes (contradiction, timeout, staleness) for deterministic characterization.

9. **Integrate approval→transition-policy test** — Chain `evaluate_destructive_approval` output into `TransitionWriter` and verify the resulting `transition_decision_review_done.json` artifact matches expected denial/accepted shape.
