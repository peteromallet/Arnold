- **Tiebreaker runtime prompts** (`prompts/tiebreaker_researcher.py`, `tiebreaker_challenger.py`, `tiebreaker_synthesis.py`): these are pure phase bodies that can be promoted to native phase implementations.

2. **`test_tiebreaker_native_flow.py`**: Does not exist. Required as S3 exit gate per master plan line 667.
3. **Replan as source-authoritative construct**: Currently `replan_state.py` side-effects state and `handle_tiebreaker_decide` mutates `state["current_state"]`. Must be an explicit typed outcome/transition in native source.
4. **Delete/fence old wrapper metadata**: `TIEBREAKER_RUN`/`TIEBREAKER_DECIDE` (components.py:2048-2100), `SOURCE_TIEBREAKER_WORKFLOW` topology contract (components.py:2532-2555), `handler_ref` declarations in `workflow.pypeline:145-176`, and `native_interfaces.py:175-207` all survive as route-capable. Per-sprint dead-delete mutation required by master plan line 672.
5. **Split-outcome scenarios**: pick/proceed, replan/iterate rejoin, escalate/override, and parent rejoin receipt scenarios (master plan line 671). The existing `test_handler_route_signals.py` only checks AST-level signal hygiene, not behavioral scenarios.

### 5. Recommended Sprint Plan Adjustment

**Current assessment**: S3 is approximately 40% done. The checker infrastructure, boundary contracts, row IDs, and receipts subsystem are solid. The gap is that the four-phase source is cosmetic — it still delegates to legacy handler dispatch — and old metadata survives undeleted.

**Recommendation**: Split S3 into two sub-sprints:

- **S3a** (the current sprint): Promote the four tiebreaker phases to true native phase bodies. The prompts already exist in `prompts/tiebreaker_researcher.py`, `tiebreaker_challenger.py`, `tiebreaker_synthesis.py`. Wire them as typed native phases instead of `handler_ref` bridges. Keep `tiebreaker_runtime.py` as the orchestration glue but ensure it's invoked through native source constructs. Add `test_tiebreaker_native_flow.py`.

- **S3b** (new): Delete/fence old wrapper metadata (`TIEBREAKER_RUN`, `TIEBREAKER_DECIDE`, `SOURCE_TIEBREAKER_WORKFLOW` topology contract). Make replan an explicit source-authoritative transition. Add dead-delete mutation proof and split-outcome scenarios. This absorption is already implied by the S3 brief ("Absorbs `m5-tiebreaker-source-extraction.md`") but the brief understates the deletion work needed given how much old metadata survives.

**Risk**: The S3 brief's "Do Not Close If — Tiebreaker source is a cosmetic wrapper around old runtime dispatch" condition currently applies. The four phases in `workflow.pypeline:471-488` pass the checker's AWF252 shape check but still route through `handle_tiebreaker_run` (each phase at `components.py:2107,2122,2137,2155` carries `# bridge: reuses legacy handler as phase body`). This is exactly the cosmetic-wrapper pattern the brief forbids.
