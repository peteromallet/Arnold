### 4. What Still Must Be Built

1. **Source-authoritative execute DAG in `.pypeline`**: Currently `workflow.pypeline:406-412` uses `parallel_map` over `EXECUTE_BATCH_WORKFLOW` (a `components.py` import). Dependency batching lives in `batch.py:2874`, not in source-visible constructs. The plan requires the DAG visible as a subworkflow or primitive (:458-459).

2. **Delete/quarantine `components.py` execute route surfaces**: `components.py:1694-1781` still declares fanout contracts, retry/reentry, skip_review_routes, batch_continuation, and review_handoff as route authority. The `EXECUTE_POLICY` at :1621 carries `branch_surface_ref` pointing to `execute.policy` but the component itself remains a dual route brain.

3. **Tests (zero exist)**: No `test_execute_native_dag_approval_resume.py` (required by master plan :702), no execute policy unit tests, no split-outcome scenarios for destructive approval denial, blocked retry, or partial resume. The scenario YAML defines `D7-execute-dag` but no test fixtures exist under `tests/arnold_pipelines/megaplan/fixtures/native_goldens/D7-execute-dag/`.

4. **Model/tier policy from source**: `resolve_batch_tier` in policy.py is pure but `_extract_execute_tier_map` in `handlers/execute.py:115` still extracts tier config from handler args/state. Tier routing must be source-owned.

5. **Batch continuation as explicit loop**: `resolve_single_batch_next_step` exists but is called from the handler (:540), not from a named source construct. The loop continuation (EXECUTE → EXECUTE) must be source-visible.

6. **Headless control injection for approval denial**: Master plan requires headless control-injection actions for destructive approval scenarios (:445-448). The handler currently raises `CliError` for denied approvals — no headless inject path.

### 5. Recommended Adjustment to Sprint Plan

S4 should be **subdivided** into two slices because the infrastructure already exists but integration depth varies:

- **S4a (pre-extraction): Policy audit + negative fixture + headless injection.** Lock down `execute/policy.py` as the source of truth, add the current-shape negative fixture mirroring `components.py:1694-1781` and `handlers/execute.py` route authority, implement headless control injection for destructive approval denial, and write the deterministic replay fixtures before any extraction begins.

- **S4b (extraction): Source-owned DAG + quarantine components.** Extract the `compute_task_batches` dependency DAG into a named subworkflow or source-visible primitive. Replace `components.py` `EXECUTE_POLICY` route authority with `.pypeline` source constructs. Write `test_execute_native_dag_approval_resume.py` with split-outcome scenarios. Dead-delete old execute route surfaces against frozen S1a baselines.

The scheduler substrate (`_core/scheduler/`) is reusable as-is; the main extraction risk is that `batch.py:3587` lines of handler-owned orchestration must be untangled without introducing regression. Baseline freeze must happen before any extraction mutates the execute loop.
