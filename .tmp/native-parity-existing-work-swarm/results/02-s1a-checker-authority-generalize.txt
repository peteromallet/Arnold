### 3. What Can Be Reused or Generalized

1. **AST-walk pattern from `_implemented_front_half_rows`** (`source_compiler.py:1695-1731`): The recursive block walker (ParsedStepCall → component_ref matching) is the exact generalization base for a structural carrier scanner. It already handles ParsedBranchBlock, ParsedLoopBlock, ParsedParallelMapCall traversal.

2. **`_front_half_row_specs` lookup pattern** (`source_compiler.py:1734-1767`): Building a `Mapping[component_ref → (row_id, phase)]` from boundary contracts generalizes to building a `Mapping[carrier_kind → classification]` from a row registry YAML.

3. **`FORBIDDEN_AUTHORITY_SCANS` shape** (`generate_native_representation_evidence.py:209-247`): The declarative `(scan_id, path, rationale, patterns)` tuple can be elevated from regex patterns to AST-level carrier-class rules with structural detection (e.g., "detect `handler_ref` assignment in canonical source", "detect `route_bindings` dict literal").

4. **`DiagnosticCode` + `diagnostic_spec` architecture**: Adding AWF253 is a ~20-line insertion in `diagnostics.py` with a corresponding diagnostic spec entry.

5. **`SemanticEvidence` / `ConstructType` model**: Can carry a `carrier_classification` field for route-authoritative vs descriptive metadata tiering.

6. **`_collect_tiebreaker_workflow_calls`** (`source_compiler.py:771-791`): Demonstrates component_ref-based AST scanning that can be generalized to detect `AUTHORING_*` imports, `handler_ref` declarations, and policy-as-route-table constructs.

### 5. Recommended Sprint Plan Adjustment

**Risk: S1a is overloaded.** The master plan (`:411-463`) combines 16+ distinct deliverables. The gap report warns S1a is the most overloaded sprint (`gpt55-native-parity-endstate-gap-report.md:98`). Suggested split:

- **S1a Core**: Row registry + structural carrier scan + AWF253 + current-shape negative fixture + structural rejection rules + checker authority tests. These gate everything else.
- **S1b Infrastructure**: Replay harness + baseline canonicalizer + control injection + installed-package smoke + baseline capture. These can be built after the core checker hardens.
- Defer `megaplan-native-representation-scenarios.yaml` completeness validation and split-outcome baseline capture to S1b or S2, since baselines must be frozen while legacy carriers are still authoritative for the flows being extracted.

**Refactor path**: The AST-scanning in `_implemented_front_half_rows` and `_collect_tiebreaker_workflow_calls` should be extracted into a shared `_scan_source_block_for_carriers(block, carrier_rules)` utility before building the full carrier scanner, avoiding duplicated traversal logic. The `FORBIDDEN_AUTHORITY_SCANS` declarative shape should be elevated into a carrier-rules schema consumed by both the structural checker and the evidence generator.
