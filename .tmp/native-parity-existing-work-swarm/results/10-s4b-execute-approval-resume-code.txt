### 4. What Still Must Be Built

1. **Unified approval surface for chain**: There is no chain entry point that accepts a destructive `approved: bool`. The evidence-pack's `resume_evidence_pack(human_input={"approved": True/False})` pattern needs to be wired into `run_chain` or a new `resume_chain` function.

2. **Destructive denial**: When `approved=False`, the system must transition the plan to a terminal rejection state (e.g., `aborted` or `failed`) with audit trail. Currently only `authority_blocked` exists for authority divergence, not for explicit human denial.

3. **Fresh-session forcing as a user-initiated command**: `_rearm_fresh_session_execute_block` is auto-triggered by `megaplan auto`. There's no CLI/user action to explicitly force a fresh-session restart with `retry_strategy: fresh_session`.

4. **Structured human handoff protocol**: The deferred-human path goes through `STATE_AWAITING_HUMAN_VERIFY` but the chain's `_awaiting_human_can_retry` is an auto-detection heuristic (reads file artifacts), not a structured protocol. The human blocker classification in `cloud/human_blockers.py` exists but isn't integrated into the chain approval flow.

5. **PhaseResult integration**: `orchestration/phase_result.py` is the new structured boundary but its adoption across phase handlers is partial. The `auto-execute-boundary-diagnosis.md` (Section 5) recommends a `phase_result.json` consumed by the auto driver — this exists but needs full integration for approval outcomes to flow cleanly.

---

### 5. Recommended Adjustment to Sprint Plan

- **S4b should be scoped as "wire existing parts, don't build from scratch."** The ladder retry, resume cursor, fresh-session rearm, and deferred-human state are all built. What's missing is the approval *decision surface* — a single `approve_plan(plan, approved: bool)` function that routes through `_handle_outcome`.

- **Highest-priority gap**: Add `approved=False` → terminal rejection to `_handle_outcome` and expose it via `run_chain` / CLI. This is the only genuinely missing capability.

- **Defer**: Full PhaseResult adoption and human-blocker classification integration into chain. These are adjacent work (S6 auto-execute boundary hardening), not S4b scope.

- **Risk**: The evidence-pack's structured approval model (`resume.py`) and the chain's outcome model (`_handle_outcome`) live in separate packages (`arnold_pipelines.evidence_pack` vs `arnold_pipelines.megaplan.chain`). Bridging them requires a conscious decision about whether to generalize the evidence-pack model into the Arnold pipeline layer or replicate it in Megaplan.
