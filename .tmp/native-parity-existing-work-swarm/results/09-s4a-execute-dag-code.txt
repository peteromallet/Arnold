### 3. What Can Be Reused or Generalized

- **`compute_task_batches`** (`_core/io.py:67`) is already a pure function — directly reusable as the dependency-scheduling primitive.
- **`blocker_recovery.py`** is already a standalone module imported by `handlers/execute.py`, `handlers/override.py`, `planning/control_binding.py`, `cli/resolutions.py`, `cli/status_view.py`, `cloud/meta_repair.py`, `auto.py` — no extraction needed.
- **`execute/policy.py`** (1085 lines) is already handler-free pure policy — `resolve_execute_entry_route`, `evaluate_destructive_approval`, `resolve_batch_tier`, `resolve_single_batch_next_step`, `evaluate_blocker_recovery_policy` are all pure functions.
- **`schedule_batches`** (`_core/scheduler/topo.py:15`) already has a documented "do not import from execute/handlers" constraint.
- The `parallel_map` compiler path for `items_ref` strings is already implemented and lowering to `FanoutPolicy(mode="dynamic")`.

### 4. What Still Must Be Built

- **No dedicated degenerate/solo execute handler for when dynamic fanout resolves to 1 batch.** The code has `single_batch_mode` optimization (`batch.py:2893-2895`) but routes through the same `handle_execute_one_batch`, not a distinct native path.
- **The `parallel_map(items="megaplan.execute.batches")` runtime resolution chain is not end-to-end tested in CI with the compiler's dynamic fanout lowering.** The compiler supports it (`source_compiler.py:5346`), but S1b-1 runtime proof of suspension/reentry and loop exit for dynamic fanout was listed as a requirement in the master plan (`master-plan.md:58-60`).
- **No dead-delete mutation test** proving old execute scheduling carriers (handler-backed auto-loop in `handlers/execute.py`) cannot route corrected behavior — this is called out as required in `gpt55-native-parity-endstate-gap-report.md:116`.
- **No frozen deterministic baseline** for execute batch scheduling outcomes.

---

### 5. Recommended Adjustment to the Sprint Plan

S4a should be **reclassified from "extract/build" to "verify/harden."** The implementation exists and is substantially complete. The sprint should:

1. **Capture golden split-outcome baselines** for dependency batching, blocked retry, tier routing, and batch continuation using the deterministic replay harness (per master plan controls).
2. **Add dead-delete mutation tests** proving old handler-backed execute routing cannot produce corrected behavior.
3. **Prove dynamic fanout runtime support** (the `items="megaplan.execute.batches"` → `FanoutPolicy(mode="dynamic")` path) with CI-verifiable suspension/reentry tests.
4. **Remove or fence** any remaining handler-owned execute routing that the policy surfaces now cover.
