### 5. Recommended Adjustment to Sprint Plan

**Split S6 into S6a (override) and S6b (auto/manifest/compat collapse).** The current evidence shows S6a is 50-60% done (override response pipeline + control adapters). S6b is ~10% done (tests written, no source changes).

**S6a scope (finish override extraction):**
- Complete `handlers/shared.py:_finish_step` source-route resolution (change #16)
- Wire override actions into source-visible policy declarations in `workflow.pypeline`
- Remove `handler_ref` from override step declaration in `workflow.pypeline:250`
- Tag `components.py:399-433` and `override_matrix.py` as quarantined metadata
- Keep the 13 passing tests green; add split-outcome scenarios for abort, force-proceed, replan, recover-blocked, resume-clarify

**S6b scope (auto/manifest/compat collapse):**
- Changes #1–15 above (route_dispatch, manifest_backend, auto.py, CLI fences)
- Compatibility quarantine report with active rejection rules (not just static scan)
- Per-sprint dead-delete mutation against frozen S1a baselines
- Exit gate: all 25 S6 tests pass; `test_override_auto_compat_quarantine.py` created; `test_megaplan_coupling_gate.py` passes

**Risk:** The current plan treats S6 as one monolithic sprint. The failing tests prove the auto/manifest/CLI fences are entangled and will require coordinated changes across 5+ files. Splitting lets override close independently and reduces the blast radius of the auto/manifest changes.
