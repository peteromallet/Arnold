# NBF-08 control-surface inventory

Read-only inventory for NBF-08 S3–S6. This is an Oracle research artifact,
not a source or tasklist change. It enumerates mutation/control entry points
that need a bound `ChainControlJournal` operation context, or an explicit
linked-domain exclusion.

## Evidence and vocabulary

- Candidate branch: `reconcile/nbf-attempt4-2297`.
- Candidate HEAD observed during inventory: `7453b3e57d`.
- The current NBF08 brief and addendum are reviewed separately; this file
  does not alter either.
- A historical manager review may be recorded as optional evidence at
  `.oracle/research/nbf08-review-adjudication.md` (the observed digest was
  `66fda12f9b9c30acbdb6ab6724543b09f671ab7a296526a4aa45dea4d0ff0776`), with
  role `manager-evidence-non-authoritative`. It is not an S7 prerequisite or
  authority input: a manager verdict cannot change this census, select a
  ledger authority, or waive a held row.
- `CTX` means a planned typed context containing chain/epic identity,
  operation ID, actor, expected physical/control cursor, expected revision,
  source/spec/config/runtime identity, and authority mode.
- `LINK` means the domain remains authoritative in its own ledger/store, but
  a chain-bound mutation must carry `chain_operation_id` and a chain event or
  receipt reference. It must not be copied into a second journal.
- `READ` means pure inspection and deliberately outside mutation history.
- `AMBIG` means the path or its direct writers require an implementation-time
  census before NBF08 can claim closure.
- The table's legacy `Class` labels map to the brief's machine labels as
  follows: `IN-SCOPE` → `chain-authoritative`, `LINK` → `linked-domain`,
  `READ` → `read-only`, and `AMBIG` → `external-unknown` with `status: held`.
- Closure records use the brief's vocabulary: `covered`, `held`, or
  `excluded`, with `ambiguity_ids`, `gate_ids`, stable `coverage_tests`, exact
  `required_commands`, `evidence_paths`, `evidence_digests`, `authority_mode`, and a
  `replay_contract`. `closure_status` is the implementation state for that
  row (`planned`, `implemented`, `verified`, `held`, or `excluded`) and is not a substitute for
  the top-level coverage status.
- For this research census, `IN-SCOPE` and `LINK` rows serialize as
  `status: covered` with `closure_status: planned`, `READ` rows as
  `status: excluded`/`closure_status: excluded`, and `AMBIG` rows as
  `status: held`/`closure_status: held` with an ambiguity ID and reason.
- The table's event-family entries are the brief's `chain_control.<kind>`
  suffixes (for example, `intent` means `chain_control.intent`); the only
  claimless entry is `None; read-only` on CC-044. `LINK` rows retain the
  existing domain's claim/receipt authority and add only chain-control links.
  The legacy shorthand `tamper` still present in earlier rows is serialized
  as the frozen `chain_control.tamper_detected` kind; no other event kind is
  implied by that shorthand.
- `claim_class` is explicit in every generated row: `required` for
  `chain-authoritative`, `linked` for `linked-domain`, `evidence-only` for a
  gate/observation that does not mutate domain state, `claimless-read` for
  `read-only`, and `held` for `external-unknown`. Every mutating `required` or
  `linked` row has the progression `intent → authority_validated → claimed →
  committed|rejected|cas_conflict|tamper_detected|replay|reconcile_required|hold`;
  external effects additionally require `external_effect_intent →
  external_effect_result`. A row may omit a phase only when its explicit
  `claim_class` justifies it, and the S7 generator must reject an unjustified
  omission.
- All source `path` values in the generated closure are repo-relative. For the
  compact human table, a module path without the `arnold_pipelines/megaplan/`
  prefix is normalized by prepending that prefix (for example,
  `arnold_pipelines/megaplan/chain/spec.py` becomes `arnold_pipelines/megaplan/chain/spec.py`);
  `arnold/runtime/*`, `.oracle/*`, `sync-skills.sh`, and `tests/*` retain their
  explicit repository-root paths. The generator must perform and validate this
  normalization rather than leaving ambient package-relative paths.
- The read-only MG gap sweep was checked at SHA-256
  `8c4abd13a5c77fbd4c4d337cd2354ef285418ca006653272f484bfcd479f443d`.
  It is review evidence only; it cannot expand chain authority or waive a
  missing route. Confirmed gaps are represented below by stable CC rows.

second; neither command is an implicit NBF07 execution.

## Deterministic per-row closure bindings

The S7 output expands every table row into a closure record; no row may rely
on a reviewer-only assertion. For row `CC-NNN`, the stable negative-test ID is
`NBF08-{lowest gate in Owner}-TNNN` (for example, `CC-064` is
`NBF08-S4-T064`), and the row's `gate_ids` contains every gate named in its
Owner column. `required_commands` is the exact command in the corresponding
gate row above, in gate order; `evidence_paths` is always
`.oracle/evidence/nbf08-chain-control-surface-inventory.json` plus any
operation receipt named by the row. `evidence_digests` contains the SHA-256 of
each such artifact, never a prose citation. `claim_class` is derived from the
row's authority class using the mapping above and is emitted alongside
`authority_class`; `ambiguity_ids` is empty unless the row is in the ambiguity
register. This convention gives every current and future row a stable test ID,
exact command, evidence path/digest, claim class, and gate binding without
renumbering existing IDs.
